# マイクのクリッピング警告を実装する

Created: 2026-10-29
Model: DeepSeek V4.1 Flash 1017
優先度: P1
対応 ADR: ADR-0002 (docs/adr/0002-web-audio-recording-and-chunks.md)
関連 PRD: R-3、非機能要件の録音の信頼性
依存: 0010

## 背景

60 分の連続録音テストで、マイク入力のピークが 1.0 に達した。
ピークが 1.0 の場合はサンプルが飽和しており、文字起こしの品質が下がる可能性がある。
現在の入力レベル表示はピークと RMS を出しているが、クリッピングの警告はない。
60 分テストのマイクの RMS は 0.004707 で、入力は小さめだった。
クリップしたサンプル数を測ってから、警告の閾値を決める。

## 目的

録音中にマイク入力のクリッピングを検出し、利用者に入力ゲインの調整を促す。

## やること

- 入力レベルのピークが 1.0 に達した回数、または 1.0 に近い状態が続いた時間を記録する。
- クリッピングが一定回数または一定時間を超えたら、録音画面に警告を出す。
- 警告には、macOS の入力音量、マイクのゲイン、マイクとの距離を調整する案内を含める。
- MVP ではアプリ内のゲイン調整機能を入れない。
  取得後のゲインでは飽和したサンプルは戻らないため、利用者に録音前の入力調整を案内する。
- クリッピングの発生を `meta.json` に記録し、録音後に確認できるようにする。
- 内蔵マイクと USB マイクでテストする。
  AirPods 入力は HFP の品質低下があるため、クリッピング警告の動作確認としてのみ行い、推奨構成としない。
- 小さい音の会議で警告が誤発火しないよう、閾値と継続時間を調整できるようにする。

## 完了条件

- 大きな入力でピークが 1.0 に達すると、録音中にクリッピング警告が出る。
- M0 の Zoom / Meet 300 秒の録音を基準に、通常の会議の音量では警告が出ない。
- 警告の発生が `meta.json` に残る。
- 自動でゲインを変更しない。
- 内蔵マイクと USB マイクでテスト結果が記録される。
