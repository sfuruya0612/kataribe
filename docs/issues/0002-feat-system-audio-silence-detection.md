# システム音声のルーティング確認と無音検出を実装する

Created: 2026-10-29
Model: DeepSeek V4.1 Flash 1017
優先度: P0
対応 ADR: ADR-0003 (docs/adr/0003-system-audio-virtual-device.md)、ADR-0002 (docs/adr/0002-web-audio-recording-and-chunks.md)
関連 PRD: R-3、非機能要件の録音の信頼性
依存: 0001

## 背景

録音中に macOS の音声出力を Multi-Output Device からスピーカーへ切り替えるテストを行った。
BlackHole のフレームは届き続けたが、非ゼロのサンプル数は 132,246 で増えなくなり、無音になった。
マイクは最後まで非ゼロのサンプルが増え続けた。
現在の判定はピークが一度でも出れば成功になるため、出力が外れたことを検知できない。

会議が始まる前の無音と、出力設定が外れた無音は区別する必要がある。
録音開始直後の無音をすぐエラーにすると、会議の開始前に録音した場合に誤警告になる。

## 目的

システム音声が BlackHole に届いていない状態を、録音中に検出して利用者に知らせる。
出力設定を直したら録音を継続できるようにする。

## やること

- BlackHole 入力の直近の RMS を、スライディングウィンドウで監視する。
  ウィンドウの長さと無音とみなす閾値は設定可能にする。
- 録音開始後、一定の猶予時間は無音でも警告しない。
  猶予時間を過ぎても無音が続く場合に、システム音声が届いていない可能性を警告する。
- 警告には、Multi-Output Device と macOS の出力設定を確認する導線を含める。
- 出力設定を直して入力レベルが戻ったら、警告を自動で消す。
- 無音が続いても、マイクだけの録音に自動で切り替えない。
  利用者が明示的に選んだ場合だけ、マイクだけの継続を許可する。
- `meta.json` に、無音検出の開始時刻、警告の発生、復旧の時刻を記録する。
- 設定画面のテスト録音でも、同じルーティング確認を使う。
- 出力デバイスを変更したときの挙動を、録音中と停止中の両方でテストする。

## 完了条件

- 録音中に出力を Multi-Output Device から外すと、猶予時間の後に警告が出る。
- 出力を戻すと、警告が消えて録音が継続する。
- 会議開始前の無音では、猶予時間内は警告が出ない。
- マイクだけの録音に自動で切り替わらない。
- `meta.json` に警告と復旧の時刻が残る。
- 出力デバイス変更のテストが自動テストまたは手動チェックリストに含まれる。
