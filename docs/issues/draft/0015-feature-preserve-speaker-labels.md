# 再文字起こしで話者ラベルと話者名を保持する

- Requirements: なし (REQ-DIAR-001 は話者名の変更を定めるが、再文字起こし後の保持と話者分離の再利用は定めていない。実装前に PRD の要求追加を検討する)
- Priority: Medium
- Created: 2026-11-01
- Model: DeepSeek V4.1 Flash 1017
- Branch: feature/feature-preserve-speaker-labels

## 目的

再文字起こしのたびに話者分離を実行し直さず、保存済みの話者ターンを新しい文字起こしセグメントに再割り当てする。
手で付けた話者名を、同じ音声と同じ話者分離設定の再文字起こし後も保持する。

## 優先度根拠

モデル変更や失敗時の再実行で再文字起こしが起きるたびに、話者名を付け直す必要がある。
60 分の音声の話者分離に約 4 分かかるため、同じ音声で同じ結果になる処理を繰り返すコストも無視できない。

## 現状

`ProcessingCoordinator.transcribe` は、話者分離が有効なとき、文字起こしが完了するたびに `runDiarization` を呼ぶ。
再文字起こしは `transcript.md` を作り直し、`meta.speakers` を新しい自動ラベルで上書きする。
話者分離の生ターンは保存していないため、同じ音声と同じ設定でも CLI を毎回実行する。
部分文字起こしの保存時には `clearDiarization` が `meta.speakers` を削除するため、旧ラベルは部分結果の時点で見えなくなる。
`transcript.ja.md` と `transcript.en.md` は残るが、話者ラベルは古いままになる。
ADR-0020 は「再文字起こしをすると話者ラベルは自動ラベルに戻る。話者名は会議ごとに付け直す」と記録している。

再現:

1. 話者分離を有効にして文字起こしを完了する。
2. 会議詳細で `話者A` を `田中`、`話者B` を `佐藤` に変更する。
3. 同じ会議を再文字起こしする。
4. `transcript.md` の話者名が `話者A` と `話者B` に戻り、`田中` と `佐藤` は失われる。

## 設計方針

### キャッシュするもの

話者分離の生ターンと、クラスタ ID ごとの話者名を保存する。

- ターン: 開始秒、終了秒、クラスタ ID
- 話者名: クラスタ ID から表示名への対応
- キャッシュキー: 話者分離の入力 16 kHz WAV の SHA-256、セグメンテーションモデルの SHA-256、埋め込みモデルの SHA-256、話者数設定、クラスタ閾値、キャッシュ形式のバージョン

whisper のモデルと文字起こしセグメントはキーに含めない。
ターンは音声だけで決まり、新しいセグメントへの再割り当ては毎回行えるためである。

### キャッシュヒット時

CLI を起動せず、保存済みターンを新しい文字起こしセグメントに再割り当てする。
クラスタ ID に話者名があればその名前を、なければ自動ラベルを付ける。
話者名はクラスタ ID で保持するため、セグメントの順序が変わって自動ラベルの順が変わっても名前を維持できる。

### キャッシュミス時

CLI を実行し、生ターンとクラスタ ID ごとの自動ラベルを保存する。
音声、セグメンテーションモデル、埋め込みモデル、話者数、閾値のいずれかが変わった場合は、古いクラスタ ID と新しいクラスタ ID が対応しないため、話者名は自動ラベルに戻す。
キャッシュの読み込みに失敗した場合と書き込みに失敗した場合は、文字起こしを失敗させずに通常の話者分離を続ける。

### 話者名の更新

会議詳細の「話者名を編集」は、`transcript.md` と翻訳を書き換えるのと同じ操作で、クラスタ ID の話者名も更新する。
現在の表示名からクラスタ ID を引けるよう、キャッシュに表示名とクラスタ ID の対応も保存する。
翻訳は、話者名を保持している行だけを新しい表示名に置き換える。話者名を保持していない行は変更しない。
要約は自動で書き換えない。話者名を変えた後に要約を再生成するかは利用者が決める。

### 保存場所

会議フォルダに `diarization.json` を置く。
会議フォルダをコピーすればキャッシュも移り、会議を削除すればキャッシュも消える。
`meta.json` は会議のメタデータとして小さく保ち、ターンの配列を持たせない。

### 範囲外

- 話者分離だけを再実行する UI。再文字起こしをせずにキャッシュを更新する操作は別 issue とする。
- 音声が変わった場合の話者名の引き継ぎ。クラスタ ID が変わるため対応しない。
- 手動で文字起こしの話者名を書き換えた場合の追跡。対応する操作は「話者名を編集」に限定する。
- 要約の話者名の自動更新。

## 完了条件

- [ ] 同じ音声と同じ話者分離設定で再文字起こししたとき、話者分離の CLI を起動せず、保存済みターンを使う。
- [ ] 同じ条件で再文字起こししたとき、クラスタ ID に付けた話者名が `transcript.md` と、話者名を保持している翻訳に残る。
- [ ] 音声、セグメンテーションモデル、埋め込みモデル、話者数、閾値のいずれかが変わったとき、キャッシュを無効化して CLI を再実行する。
- [ ] キャッシュが壊れている、読めない、書けない場合でも、文字起こしと話者分離は完了する。
- [ ] 部分文字起こし、失敗、キャンセルの後でも、キャッシュと話者名は失われない。
- [ ] 会議を削除すると `diarization.json` も削除される。
- [ ] キャッシュキーの一致と不一致、再割り当て、話者名の保持、無効化、破損時のフォールバックをテストで固定する。
- [ ] `npm run typecheck`、`npm test`、`npm run build`、`npm run package`、`npm run verify:mac` が通る。
- [ ] PRD、ADR、CHANGES.md、README を同じ変更で更新する。

## 解決方法

- `src/main/diarization-cache.ts` を追加する。
  - `DiarizationCache` の型、`schema_version`、読み書き、キャッシュキーの比較、破損時の扱いを持つ。
  - 保存先は `join(meeting.meetingDir, 'diarization.json')` とする。
- `src/main/diarization.ts` を拡張する。
  - `DiarizationService` が表示用セグメントだけでなく、生ターンとクラスタ ID、自動ラベルの対応を返せるようにする。
  - `assignSpeakerTurns` にクラスタ ID ごとの話者名を受け取る引数を追加する。
  - 16 kHz WAV の SHA-256 を計算する。既存の `hashFile` を使う。
- `src/main/processing.ts` を変更する。
  - 話者分離の前に `diarization.json` を読み、キーが一致すれば CLI を実行せずに再割り当てする。
  - 実行後と話者名の変更後に `diarization.json` を書く。
  - 部分文字起こしと失敗時は `meta.speakers` を消しても `diarization.json` は消さない。
- `src/main/meetings.ts` を変更する。
  - `renameSpeakers` でクラスタ ID の話者名を更新する。
  - `detail` の話者一覧は、キャッシュの話者名と `transcript.md` の表示名から作る。
- テストを追加する。
  - キャッシュキーの一致、不一致、モデル変更、話者数変更。
  - 新しいセグメントへの再割り当てと、自動ラベルの順が変わった場合の名前の保持。
  - 部分文字起こし、失敗、キャンセル後のキャッシュ保持。
  - `diarization.json` の破損、読み込み失敗、書き込み失敗。
  - 翻訳の話者名の置換。
- `docs/prd/kataribe.md` のデータ設計に `diarization.json` を追加し、要求 ID と受入基準を追加する。
- 設計判断は ADR に記録する。保存場所、キャッシュキー、無効化、話者名の対応を扱う。

## 未決事項

- PRD の要求 ID を新設するか、`REQ-DIAR-001` を拡張するか。要求の意味が変わるため、新しい ID を起こす必要がある。
- キャッシュキーの音声ハッシュを 16 kHz WAV にするか、mp3 と変換設定にするか。16 kHz WAV は毎回生成するが、入力そのものを固定できる。
- スレッド数をキャッシュキーに含めるか。結果がスレッド数に依存しないことを実測で確認する必要がある。
- 話者分離モデルを変えた場合に、クラスタ ID の話者名を引き継ぐか。クラスタ ID の対応が保証できないため、現案は自動ラベルに戻す。
- 翻訳の話者ラベルをどの時点で置換するか。再文字起こし時か、話者名の変更時だけか。
- `meta.speakers` と `diarization.json` の話者名のどちらを表示の正とするか。二重管理を避ける必要がある。
- 話者分離だけを再実行する UI をこの issue に含めるか、別 issue にするか。
- キャッシュのサイズ上限と、長い会議での `diarization.json` の大きさ。
