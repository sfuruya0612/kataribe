# 既存の文字起こしに話者分離だけを再実行する

- Requirements: なし (REQ-DIAR-001 と REQ-DIAR-002 は再文字起こし時の話者分離を定めるが、既存の文字起こしだけに話者分離を適用する UI は定めていない。実装前に PRD の要求追加を検討する)
- Priority: Low
- Created: 2026-11-01
- Model: DeepSeek V4.1 Flash 1017
- Branch: feature/feature-rerun-diarization

## 目的

文字起こしをやり直さずに、既存の `transcript.md` へ話者分離だけを適用する。
話者分離を後から有効にした会議や、話者分離だけをやり直したい会議で、文字起こしの編集内容を保ったまま話者ラベルを付ける。

## 優先度根拠

話者分離を後から有効にした会議は、現在は文字起こしをやり直すしかない。
文字起こしの編集内容を失わずに話者ラベルだけを付ける要求はあるが、話者分離のキャッシュ (issue 0015) が入ってから実装できる。

## 現状

会議詳細の「文字起こしを再実行」は、文字起こしが存在しないときだけ表示する。
文字起こしが存在する会議では、話者分離を有効にしても話者ラベルを付ける操作がない。
`transcript.md` は各行の開始時刻だけを持ち、終了時刻を持たない。
話者分離の入力 16 kHz WAV は文字起こし完了後に削除される。

## 設計方針

- 会議詳細に「話者分離を再実行」を追加する。
- 16 kHz WAV を mp3 または audio.wav から再生成し、保存済みの話者ターンがあれば再利用する。
- `transcript.md` の各行を開始時刻と本文に分け、終了時刻は次の行の開始時刻または会議の長さから決める。
- 話者ターンと各行の重なりで話者を割り当て、`diarization.json` と `transcript.md`、翻訳を更新する。
- 文字起こしの本文、行数、開始時刻は変更しない。
- 話者分離のキャッシュがない場合は、CLI を実行する。
- 既存の話者名がある場合は、クラスタ ID の対応が一致するときだけ引き継ぐ。

## 完了条件

- [ ] 文字起こしが存在する会議で「話者分離を再実行」を押すと、本文を変えずに話者ラベルが付く。
- [ ] 話者分離のキャッシュがある場合は CLI を実行しない。
- [ ] 実行中、失敗、キャンセルの扱いを会議詳細に表示する。
- [ ] 再実行後も文字起こしの編集内容と既存の話者名が保持される。
- [ ] テストで、本文不変、ラベル変更、キャッシュ利用、失敗時の保存を固定する。
- [ ] `npm run typecheck`、`npm test`、`npm run build`、`npm run package`、`npm run verify:mac` が通る。
- [ ] PRD、ADR、CHANGES.md、README を同じ変更で更新する。

## 解決方法

- `src/main/processing.ts` に話者分離だけを実行する処理を追加する。
- `src/main/meetings.ts` に `transcript.md` の開始時刻からセグメントを復元する処理を追加する。
- `src/renderer/src/MeetingDetail.tsx` に「話者分離を再実行」を追加する。
- preload と `env.d.ts` に IPC を追加する。
- テストは `tests/processing.test.ts`、`tests/meetings.test.ts`、`tests/diarization.test.ts` に追加する。
