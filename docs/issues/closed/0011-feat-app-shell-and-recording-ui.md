# メニューバーと録音画面、設定画面の土台を作る

Created: 2026-10-29
Model: DeepSeek V4.1 Flash 1017
Completed: 2026-10-29
優先度: P0
対応 ADR: ADR-0012 (docs/adr/0012-menu-bar-and-main-window.md)
関連 PRD: R-1、R-2、R-3
依存: 0009、0010

## 背景

ADR-0012 は、メニューバーに常駐し、メインウィンドウに会議一覧、会議詳細、設定の 3 画面を持つと決めている。
録音の状態、経過時間、入力ソースはメインプロセスに集約し、トレイと Renderer は IPC で状態を受け取る。
録音中核は issue 0010 で作るが、利用者が録音を開始、停止し、入力ソースとレベルを確認する UI がない。

## 目的

メニューバー、メインウィンドウ、録音パネル、設定画面の土台を作り、録音中核と IPC でつなぐ。

## やること

- メニューバーのトレイに、録音の開始と停止、入力ソースの切り替え、経過時間、メインウィンドウを開く項目、終了を置く。
- メインウィンドウに、会議一覧、会議詳細、設定の 3 画面の土台を作る。
  会議一覧と会議詳細の本実装は、別の issue に分ける。
- 録音パネルに、録音の開始と停止、経過時間、入力レベル、入力ソース、録音状態を表示する。
- 設定画面に、保存先フォルダ、whisper.cpp モデル、LLM プロバイダ、要約の出力言語、BlackHole 2ch のセットアップへのリンクを置く。
  各設定の本実装は、別の issue に分ける。
- 録音の状態、経過時間、入力ソース、入力レベルはメインプロセスを唯一の状態とし、トレイと Renderer に IPC で通知する。
  Renderer 側に別の録音状態を持たない。
- アプリのインスタンスを 1 つに制限し、2 つ目の起動では既存のウィンドウを前面に出す。
- メインウィンドウを閉じたときはアプリを終了せず、トレイに残す。
- macOS のアプリメニューに About 画面を置き、アプリ名とバージョンを表示する。
  BlackHole 2ch の出典表示は issue 0007 で追加する。
- 録音中は Renderer の background throttling を無効にする。
- トレイの操作、状態の同期、ウィンドウの閉じる動作、入力ソースの同期をテストする。

## 完了条件

- トレイに録音の開始と停止、入力ソース、経過時間、メインウィンドウを開く項目、終了が表示される。
- メインウィンドウに会議一覧、会議詳細、設定の 3 画面と録音パネルが表示される。
- トレイと設定画面の入力ソースが同期する。
- メインウィンドウを閉じてもアプリが終了せず、トレイから開き直せる。
- アプリメニューから About 画面を開け、アプリ名とバージョンが表示される。
- 録音の状態がメインプロセスに集約され、Renderer に重複した状態がない。
- 録音中にメインウィンドウが背面にあっても、録音が継続する。

## 解決方法

2026-10-29 にメニューバーと画面の土台を実装した。

- メインプロセスに `RecordingStateStore` を追加した。
  録音状態、入力ソース、経過時間、入力レベル、チャンク数、直近の結果を保持する。
  `starting`、`recording`、`stopping`、`encoding`、`error` の状態を扱う。
- `RecordingCoordinator` を追加した。
  開始と停止の要求を状態と照合し、Renderer に `recording:command` を送る。
  トレイの操作と画面のボタンは同じ経路を使う。
- トレイを追加した。
  左クリックで録音を開始または停止する。
  右クリックのメニューに状態、経過時間、録音の開始と停止、入力ソース、メインウィンドウを開く項目、終了を置いた。
  トレイの画像は `scripts/generate-tray-icon.py` で生成するテンプレート画像を使う。
- メインウィンドウに録音パネル、入力レベル、保存結果、復旧、会議一覧、会議詳細、設定の土台を追加した。
  会議一覧、会議詳細、設定の本実装は次の issue に分ける。
- 入力ソースはメインプロセスの状態を正とし、トレイ、録音パネル、設定画面が同じ値を表示する。
  録音中に変更した場合は選択値だけを更新し、録音中のセッションの入力ソースは変えない。
- メインウィンドウを閉じるとウィンドウを隠し、アプリは終了しない。
  `KATARIBE_WINDOW_TEST=1` で、`BrowserWindow.close()` の後にウィンドウが破棄されず非表示になることを確認する。
- Renderer が再読み込みされた場合と、Renderer のプロセスが終了した場合は、録音中のセッションを停止してチャンクを保存する。
- macOS のアプリメニューに About 画面を追加した。
  アプリ名は `Kataribe 会議録`、バージョンは `app.getVersion()` を使う。
- 設定画面に保存先、whisper.cpp モデル、LLM プロバイダ、要約の出力言語、マイク権限、BlackHole 2ch のセットアップ、About を置いた。
  設定値の保存とモデルのダウンロードはまだ実装していない。
  保存先は現時点で `~/Documents/Kataribe/` 固定である。
- パッケージにトレイ画像と README を含めた。
  README は設定画面のセットアップ手順から開く。

確認結果:

- `npm run typecheck`: 成功。
- `npm test`: 69 件成功。
  状態ストア、調整役、トレイメニュー、録音中核、AudioWorklet、録音ユーティリティをテストする。
- `npm run build`、`npm run smoke`、`npm run package`: 成功。
- `npm run test:window`: `KATARIBE_WINDOW_TEST_OK`。
  メインウィンドウを閉じてもアプリが終了せず、ウィンドウが非表示になることを確認した。
- パッケージ済みアプリの smoke test とウィンドウテスト: 成功。
- 開発版の実機確認:
  - 設定画面で入力ソースを変更すると、メインプロセスの状態と録音パネルの表示が一致した。
  - トレイと同じ `recording:request-start` 経由で録音を開始できた。
  - 録音中に入力ソースを変更すると、選択値だけが変わり、録音中のセッションの入力ソースは変わらなかった。
  - 14 秒の録音中にウィンドウを閉じても録音が継続した。
    ウィンドウを閉じた後の経過時間は 2.5 秒から 5.0 秒に増えた。
    2 つ目の起動で既存のウィンドウが前面に戻り、録音を停止すると 687,232 サンプル、2 チャンクを保存できた。
  - 会議一覧、会議詳細の 3 タブ、設定画面、About 画面を表示できた。
- パッケージ済みアプリの実機確認:
  - トレイを作成できた。
  - 入力ソースをシステム音声にして 4 秒録音し、201,856 サンプルを保存できた。
  - 会議一覧、会議詳細、設定の 3 画面を表示できた。

残っている作業:

- 会議一覧と会議詳細の本実装を次の issue で行う。
- 設定値の保存、whisper.cpp モデルのダウンロード、LLM プロバイダの管理は次の issue で行う。
- トレイのアイコンの状態表示、Dock に表示するかどうか、最後に開いた画面の復元は未決事項である。
- 60 分の連続録音は issue 0006 の回帰テストで確認する。
