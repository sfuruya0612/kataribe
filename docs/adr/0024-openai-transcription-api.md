# ADR-0024: OpenAI の文字起こし API を任意のエンジンとして追加し、音声送信の確認を必須にする

- Status: Accepted

## Context

Kataribe の文字起こしは、端末内の whisper.cpp を子プロセスで実行する(ADR-0006)。
文字起こしの精度はモデル、音声品質、用語集に依存し、利用者は会議の内容によって精度が足りないと感じる場合がある。
利用者から、OpenAI の文字起こし API を Whisper の代わりに使えるようにしたいという要求がある(PRD の `REQ-TRANS-001`)。

OpenAI の文字起こし API は `whisper-1` で `verbose_json` を返し、区間ごとの開始時刻、終了時刻、本文、言語を含む。
`gpt-4o-transcribe` と `gpt-4o-mini-transcribe` は `json` だけを返し、区間のタイムスタンプを含まない。
`whisper-1` のリクエストは 25 MiB 以下に制限される。
60 分の会議を 16 kHz モノラルの WAV にすると約 115 MB になるため、1 リクエストでは送れない。

ADR-0013 は、音声を端末外に送らないことをプライバシー境界としている。
OpenAI の文字起こし API を使うと、音声が端末外に出る。
利用者が明示的に選んだ場合だけこの境界を越え、送信のたびに内容と送信先を確認できる必要がある。
API キーは safeStorage に保存する(ADR-0009)。

## Decision

- 文字起こしエンジンを `whisper-cpp` と `openai` から選べる設定を追加する。
  既定は `whisper-cpp` とする。
- OpenAI の文字起こしモデルは `whisper-1`、`gpt-4o-transcribe`、`gpt-4o-mini-transcribe` から選べる。
  既定は `whisper-1` とする。
  `whisper-1` 以外のモデルは区間のタイムスタンプを返さないため、分割した音声の区間を 1 つのセグメントとして保存し、設定画面にその制約を表示する。
- OpenAI の API キーは、Provider が ChatGPT の LLM プロファイルに保存したキーを使う。
  文字起こし専用の API キーを別に保存しない。
  利用者が ChatGPT のプロファイルを 1 つ用意すれば、要約と文字起こしで同じキーを使える。
- OpenAI の文字起こしを使うときは、文字起こしの開始前に、送信先のホスト、モデル、音声の長さ、分割数、音声が端末外に出ることを示す確認ダイアログを出す。
  利用者が承認したときだけ音声を送る。
  承認しなかったときは音声を送らず、ローカルの whisper.cpp で文字起こしを続ける。
- 16 kHz モノラルの WAV を 25 MiB 以下の区間に分割する。
  区間の長さは最大 10 分とし、区間の境界は手前 5 秒の範囲で最も静かな位置に寄せる。
  各区間の文字起こしの時刻に区間の開始時刻を加算し、1 つの文字起こしに結合する。
- リクエストが 429 または 5xx で失敗したときは、指数バックオフで初回を含めて最大 3 回試行する。
  ネットワークエラーと不正な JSON 応答も同じ回数だけ試行する。
  400、401、403、404、413 は再試行せず、設定または入力の誤りとして扱う。
  途中の区間まで成功したときは、その結果を部分的な文字起こしとして保存する。
- 送信するのは文字起こし用の音声と、モデル名、用語集、応答形式だけとする。
  会議のタイトル、日付、保存先のパス、API キー、その他のメタデータは送らない。
- ログに残すのは、モデル名、HTTP ステータス、所要時間、分割数、トークン数だけとする。
  音声、文字起こしの本文、API キーはログに残さない。
- ADR-0013 の「音声を端末外に送らない」という決定に、OpenAI の文字起こしを利用者が明示的に選んだ場合の例外を設ける。
  要約と翻訳では音声を送らないという決定は維持する。

## Consequences

- OpenAI の文字起こしを使うと、音声が端末外に出る。
  利用者は送信のたびに確認ダイアログで判断するため、録音停止から文字起こし完了までの操作が 1 回増える。
- `whisper-1` は区間のタイムスタンプを返すため、既存の音声位置への移動と検索を維持できる。
  `gpt-4o-transcribe` と `gpt-4o-mini-transcribe` は区間のタイムスタンプを返さないため、10 分単位の粗い位置になる。
- 25 MiB の上限に合わせて分割するため、区間の境界で単語が切れる可能性がある。
  最も静かな位置に境界を寄せることで影響を抑えるが、境界をまたぐ発話の精度は保証できない。
- ネットワークと OpenAI の可用性に依存する。
  429 と 5xx の再試行で一時的な失敗を吸収するが、長い障害では部分結果だけが残る。
- ChatGPT のプロファイルを削除または変更すると、文字起こしに使う API キーも変わる。
  文字起こし専用のプロファイルを作れば、要約の設定変更から切り離せる。
- 既定はローカルの whisper.cpp のままなので、オフライン要件と既存の利用者の動作は変わらない。
- OpenAI の音声の保存と学習の扱いは、OpenAI の規約に従う。
  アプリは送信先のデータの扱いを保証しない。
