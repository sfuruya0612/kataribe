# ADR-0007: 文字起こしの完了判定と打ち切りを進捗ベースにする

Created: 2026-10-28
Model: DeepSeek V4.1 Flash 1017
Status: Accepted

## 背景

whisper.cpp は、音声の途中で処理が止まった場合でも終了コード 0 を返すことがある。
固定のタイムアウトを置くと、遅いマシンでは正常な処理を打ち切り、速いマシンでは止まった処理をいつまでも待つ。
PRD は、文字起こしの完了を終了コードだけで判断せず、最後のセグメントの位置と出力の有無で判断することを求める（PRD の T-8）。
タイムアウトも固定秒数ではなく、セグメントの進捗で判断する（PRD の T-9）。

処理が止まったときは、それまでのセグメントを部分文字起こしとして保存し、最後のセグメントの終了時刻から 1 回だけ自動で再開する（PRD の T-10）。
それでも失敗したら、1 段小さいモデルでの再実行を提案する。
Mac のスリープ中は処理が進まないため、タイマーの計時から除く必要がある。

## 決定

- 文字起こしの完了は、次の 3 つの条件をすべて満たした場合だけとする。
  - whisper.cpp のプロセスが終了コード 0 で終了した。
  - 最後のセグメントの終了時刻が、音声の長さから 15 秒を引いた時刻以上である。
  - 出力されたセグメントが 1 つ以上あり、テキストが空でない。
- 音声の長さは、16 kHz wav のヘッダーから取得する。
  取得できない場合だけ ffmpeg の出力を使う。
  ffprobe を同梱する場合は、ADR-0004 のバイナリの一覧に加える。
  最後のセグメントの終了時刻は、whisper.cpp の出力から取得する。
- 進捗は、最後のセグメントの終了時刻を音声の長さで割った値とする。
  画面には進捗の割合と、予想残り時間を表示する（PRD の T-4）。
  予想残り時間は、予想時間から経過時間を引いて計算する。
- whisper.cpp は `--print-progress` を有効にし、デコーダの進捗を標準エラーから読む。
  セグメントの出力と合わせて、処理が進んでいるかを判定する。
- 予想時間は、音声の長さに処理速度比を掛けて求める。
  処理速度比の初期値は、Apple Silicon で 0.2 とする。
  0.2 は 60 分の音声に 12 分を見込む保守的な値で、PRD の 10 分以内という目標より遅い。
  最初の文字起こしが完了したら、実際の処理時間から処理速度比を計算して保存する。
  実測値を保存すれば、2 回目以降の予想は実測に近づく。
- 停止の判定は、最後のセグメントが出てから新しいセグメントが出ない時間で行う。
  通常は 3 分、large 系のモデルでは 5 分とする。
- 保険として、予想時間の 3 倍、最低 5 分を上限の目安とする。
  上限を超えた時点で進捗が続いている場合は、利用者に継続するか停止するかを確認する。
  進捗が止まっている場合は、その時点で打ち切る。
  PRD の「進んでいる限り打ち切らない」と T-9 のハードリミットの関係は、この解釈で運用する。
- タイマーは Mac のスリープ中に進めない。
  Electron の `powerMonitor` の suspend と resume を監視し、スリープしていた時間を経過時間から除く。
- 停止、タイムアウト、または完了条件を満たさない場合は、次の順で処理する。
  - その時点までのセグメントを `transcript.md` に部分結果として書き、`meta.json` に部分結果であることと最後のセグメントの終了時刻を記録する。
  - whisper.cpp に SIGTERM を送り、一定時間待ってから SIGKILL を送る。
  - 最後のセグメントの終了時刻をミリ秒に変換し、`--offset-t` に渡して同じモデルで 1 回だけ自動的に再開する。
    この再開は、同梱する whisper.cpp が `--offset-t` に対応している場合に限る。
  - 再開した処理が完了したら、部分結果と再開後の結果を結合する。
- 自動再開は 1 回だけとする。
  再開しても完了条件を満たさない場合は、1 段小さいモデルでの再実行を提案し、自動では実行しない。
  モデルの候補は large-v3-turbo、medium、small の順に下げる。
- 利用者がキャンセルした場合も、その時点までのセグメントを部分結果として保存する。
  キャンセル後に自動再開はしない。
- `meta.json` の `status` は PRD の 7 値 (recording、encoding、enhancing、transcribing、transcribed、summarized、error) を維持する。
  部分結果、再開回数、最後のセグメントの終了時刻、エラーの種類は、`transcription` の別の項目に記録する。
  `transcription.state` は `running`、`partial`、`cancelled`、`interrupted`、`failed`、`completed` のいずれかとする。
- アプリの起動時に、`status` が `recording`、`encoding`、`enhancing`、`transcribing` のまま残っている会議を検出する。
  これらは `interrupted` として扱い、残っているファイルから復旧する操作を画面に出す。
  `enhancing` のときは `meta.status = error` とし、`enhancement.json` の該当 state を `interrupted` に更新する。
- エラーは、タイムアウト、プロセスのクラッシュ、空の出力、出力の途中切断、モデルの読み込み失敗、ディスクの書き込み失敗に分類する。
  画面には分類ごとのメッセージを出し、再実行の操作を用意する。
- エンコードにも音声の長さに応じたタイムアウトを設ける。
  最低 5 分、音声の長さの 5 倍を目安とし、超えたら ffmpeg を SIGTERM と SIGKILL で停止して `error` にする。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| 固定のタイムアウトを置く | 遅いマシンでは正常な処理を打ち切り、速いマシンでは止まった処理を待ち続ける。PRD の T-9 に反する |
| 終了コードだけで完了を判断する | whisper.cpp が途中で止まっても終了コード 0 を返す場合があり、途中までの文字起こしを完了として扱ってしまう |
| セグメントの進捗を無視して無期限に待つ | 利用者が停止を判断できず、会議の処理が終わらない |
| 停止したら最初からやり直す | すでに処理した音声をもう一度処理することになり、時間がかかる。`--offset-t` で続きから再開できる |
| 停止したら自動で小さいモデルに切り替える | モデルを下げると精度が落ちる。まず同じモデルで 1 回再開し、それでもだめなら利用者に提案する |
| キャンセル時に部分結果を捨てる | 利用者が途中までの結果を活用できない。部分結果を残しても害はない |
| CPU 使用率で停止を判定する | whisper.cpp は Metal と CPU を併用するため、CPU 使用率だけでは停止と高負荷を区別できない |
| スリープ中もタイマーを進める | スリープから復帰した直後に、実際には処理が進んでいないのにタイムアウトする |

## 結果

- 文字起こしのジョブに、進捗の監視、停止の判定、部分結果の保存、再開、エラー分類の状態機械が必要になる。
  状態遷移をメインプロセスのジョブ管理に集約し、画面は状態を表示するだけにする。
- 停止の判定を 3 分または 5 分にすると、難しい音声区間で whisper.cpp が長く考えている場合に、正常な処理を停止と誤判定する可能性がある。
  誤判定が起きた場合は、閾値とハードリミットを調整する。
- 進捗が続いているのに予想時間の 3 倍を超えた場合は、自動で打ち切らず、利用者に継続するか停止するかを確認する。
- 処理速度比を保存することで、2 回目以降の予想残り時間が実測に近づく。
  モデルやマシンが変わると比も変わるため、モデルごとに保存するか、全体で 1 つにするかを決める必要がある。
- `--offset-t` で再開した場合、部分結果の最後のセグメントと再開後の最初のセグメントが重複する可能性がある。
  タイムスタンプを見て重複を除く処理が必要になる。
- 部分結果を `transcript.md` に書くと、完了済みの文字起こしと区別が付きにくい。
  `meta.json` の `transcription.partial` を見て、画面と要約の生成で部分結果であることを示す。
- 自動再開を 1 回に限ることで、同じ失敗を繰り返さない。
  利用者が手動で再実行する操作は残す。
- スリープの監視を誤ると、スリープ復帰後にタイムアウトする。
  suspend と resume のイベントだけでなく、resume 後の最初のセグメントの到着も確認する。
- 文字起こしの処理時間と停止の履歴を `meta.json` に残す。
  テレメトリは送らないため、品質の改善は利用者から提供されたファイルで行う。

## 未決事項

- 同梱する whisper.cpp の版が `--offset-t` に対応しているか。
  対応していない場合は、同じモデルでの再開をあきらめ、部分結果を残して利用者に再実行を促す。
- 部分結果と再開後の結果を結合するときの重複除去の規則。
- 処理速度比をモデルごとに保存するか、アプリ全体で 1 つ保存するか。
- アプリの再起動後に、中断した文字起こしを自動で再開するか。
- 1 段小さいモデルを提案する条件と、提案するモデルの順序。
- 4 時間を超える音声のハードリミットと、録音の最大長。
- エンコードのタイムアウトの具体的な秒数と、ffmpeg が停止した場合の再試行。
- 部分結果を要約に使えるようにするか、完了した文字起こしだけを要約の対象にするか。
