# ADR-0020: 話者分離を sherpa-onnx で行う

Created: 2026-11-01
Model: DeepSeek V4.1 Flash 1017
Status: Accepted

## 背景

現行の話者分離は、文字起こしセグメントごとの RMS、ゼロ交差率、ピッチを 3 次元の特徴量にして 2-means でクラスタリングする。
話者を常に 2 人と仮定するため、3 人以上の会議ではラベルが実態と合わない。
利用者から、2〜10 人の会議に対応したいという要求がある。
音声と文字起こしは端末内で処理する方針を維持する。
文字起こしは whisper.cpp の子プロセスで行い、話者分離も同じ 16 kHz モノラルの WAV を入力にできる。
話者分離の精度は、声質が近い場合や発話が重なる場合に下がる。

## 決定

- 話者分離に sherpa-onnx のオフライン話者分離を使う。話者セグメンテーションに pyannote segmentation 3.0、話者埋め込みに 3D-Speaker ERes2Net Base を使う。
- 話者分離の実行ファイルと ONNX Runtime をアプリに同梱し、2 つのモデルは初回利用時にダウンロードする。
- 話者数は自動検出を既定にし、2〜10 人の指定も受け付ける。自動検出が 10 人を超えた場合は 10 人で再実行する。
- 話者分離は文字起こしの完了後に実行し、得られた話者ターンを whisper.cpp のセグメントに時間の重なりで割り当てる。
- 話者ラベルは最初に現れた順に `話者A` から `話者J` とする。
- 話者名は会議ごとに変更できる。変更は `transcript.md` と、話者名を保持している既存の翻訳ファイルの話者ラベルに反映する。
- 話者分離に失敗しても文字起こしは保存し、失敗理由を会議のメタデータと会議詳細に残す。
- 既存の 2-means による簡易話者分離は削除する。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| 既存の特徴量と k-means のクラスタ数を自動決定する | ピッチと周波数特性だけでは、声質の近い 3 人以上を安定して分けられない |
| クラウドの話者分離 API を使う | 音声を端末外に送るため、プライバシー方針に反する |
| マイクとシステム音声をステレオの別チャネルで録音する | 2 者の分離は正確になるが、対面の 3 人以上と相手側の複数話者に対応できず、録音形式の変更も必要になる |
| 埋め込みモデルを Node.js のネイティブアドオンで動かす | Electron の ABI とパッケージングが複雑になる。既存の子プロセス方式から外れる |
| モデルをアプリに同梱する | アプリサイズが 300 MB の上限を超える |
| 話者分離を LLM で推定する | 音声または文字起こしを外部に送る必要があり、推定結果の再現性も低い |

## 結果

- 2〜10 人の会議で、話者ごとの発言を 1 行ずつラベル付けできる。
- 話者分離の精度は、モデルの性能と録音品質に依存する。声質が近い発話や重なり発話では誤る。
- 1 つの文字起こしセグメントに複数の話者が含まれる場合、最も長く重なった話者を 1 人だけ割り当てる。
- アプリのバイナリが約 17 MB 増える。話者分離モデルは初回利用時に約 46 MB をダウンロードする。
- 話者分離は CPU を使う。56.9 秒の音声を 4 スレッドで 3.5 秒に処理した実測値があり、60 分の音声では約 4 分になる。
- 話者分離モデルは pyannote segmentation 3.0 (MIT) と 3D-Speaker ERes2Net Base (Apache-2.0) で、ライセンス表示を追加する。
- 再文字起こしをすると話者ラベルは自動ラベルに戻る。ただし、ADR-0021 の話者分離キャッシュが一致する場合は話者名を保持する。
- ステレオ分離は採用しないため、マイクとシステム音声はモノラルに混合したまま保存する。
