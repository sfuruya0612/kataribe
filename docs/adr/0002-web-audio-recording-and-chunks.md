# ADR-0002: 録音は Renderer の Web Audio で行い、10 秒ごとの WAV チャンクを保存する

Created: 2026-10-28
Model: DeepSeek V4.1 Flash 1017
Status: Accepted

## 背景

Kataribe は、マイク、システム音声、その両方から会議音声を取得する（PRD の R-2）。
録音は 60 分の会議を取りこぼさず、録音中の CPU 使用率を 1 コアの 10% 以下に抑えることが求められる（PRD の「非機能要件」）。
アプリやマシンが落ちても、直前までの音声を復旧できる必要がある（PRD の R-5）。
録音中は経過時間と入力レベルを表示し、無音が続く場合は警告する（PRD の R-3）。
停止時には mp3 と文字起こし用の 16 kHz wav を作る（PRD の R-4）。

Electron のメインプロセスには、マイクを直接読む標準 API がない。
Renderer の `getUserMedia` と Web Audio を使えば、マイクとシステム音声のストリームを同じ `AudioContext` で扱える。
一方、Renderer から任意のファイルを書き込むことはできない。
音声のチャンクをディスクに残すには、PCM をメインプロセスに渡してファイルを書く必要がある。

録音を 1 本のファイルに書き続けると、異常終了でファイル全体が壊れる。
10 秒ごとにチャンクを確定して書き出せば、最後のチャンクより前の音声を復旧できる。

## 決定

- 録音は Renderer の `getUserMedia` と Web Audio で行う。
  マイクとシステム音声は、`enumerateDevices` で選んだ入力デバイスから取得する。
  システム音声は BlackHole 2ch などの仮想オーディオデバイスを入力デバイスとして使う（ADR-0003）。
  BlackHole が見つからない場合は、システム音声の選択肢を無効にする。
- マイクとシステム音声を同時に録るときは、同じ `AudioContext` の中で `GainNode` により混合する。
  最終的な保存形式がモノラルなので、混合後の信号はモノラルにする。
- PCM の取り出しには `AudioWorklet` を使う。
  `MediaRecorder` は使わない。
  `MediaRecorder` の圧縮チャンクは、途中で切れたときに単体で再生できず、復旧と ffmpeg への入力に向かない。
- チャンクは 10 秒ごとに WAV として確定する。
  チャンクの形式は、入力のサンプルレート、16-bit PCM、モノラルとする。
  16 kHz への変換は停止後に ffmpeg で行う（ADR-0005）。
- チャンクは Renderer から preload の API を経由してメインプロセスに渡し、メインプロセスが保存先ルートの外の一時ディレクトリに書く（ADR-0010）。
  ファイル名は `000001.wav` のような 6 桁の連番とする。
  書き込みは一時ファイルに対して行い、ファイルとディレクトリを fsync してから rename する。
  途中のファイルを確定済みのチャンクとして扱わない。
- メインプロセスはチャンクを書くたびに `meta.json` の最終チャンク番号、期待する総サンプル数、録音経過時間を更新する。
  異常終了後、`status` が `recording` のままの会議と一時ディレクトリを見つけたら、残っているチャンクから復旧できるようにする。
- 結合後に、復旧したチャンクの総サンプル数と `meta.json` の期待値が一致するか検査する。
  一致しない場合は、欠落した可能性がある旨を画面に出し、部分録音として扱う。
- 録音中の入力レベルは AudioWorklet で RMS とピークを計算し、100 ms 間隔で Renderer の画面に送る。
  無音が一定時間続いたら警告を出す。
  警告を出す閾値は未決事項とする。
- 録音の開始と停止はメインプロセスのジョブ管理に集約する。
  Renderer は録音ストリームの開始と停止を行い、状態の変更をメインプロセスに通知する。
  録音は同時に 1 件だけとし、録音中に別の録音を開始できないようにする。
- 録音中は `powerSaveBlocker` でスリープを抑止する。
  Renderer の `backgroundThrottling` は無効にし、メインウィンドウが背面にあっても音声処理を続ける。
- 録音中はメインウィンドウの再読み込み、開発時の HMR、ナビゲーションを禁止する。
  Renderer が再生成された場合は録音を停止し、残ったチャンクから復旧する。
- 入力ソースの変更は録音中は表示だけに反映し、次の録音から適用する。
- マイクの `echoCancellation`、`noiseSuppression`、`autoGainControl` の既定値を決め、設定で変更できるようにする。
  ミキサーは `channelCount: 1`、`channelCountMode: "explicit"` にする。
  `AudioContext` の実際のサンプルレートを `meta.json` に記録する。
- 停止時は最後のチャンクを確定して `AudioContext` を閉じ、メインプロセスがチャンクを結合して mp3 と 16 kHz wav を作る（ADR-0005）。
  mp3 と 16 kHz wav の生成が成功したら `chunks/` を削除する。
  `audio.16k.wav` は文字起こしが成功するまで残す。
  どちらかが失敗した場合は、復旧のために残す。
- 録音開始時に会議フォルダを作り、`meta.json` に `status: recording`、入力ソース、開始時刻、サンプルレートを書く。
  録音中にタイトルを変更してもフォルダ名は変えず、録音停止後に改名する（ADR-0010）。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| `MediaRecorder` で WebM や Opus のチャンクを書く | チャンク単体では再生できず、異常終了時の復旧と ffmpeg での結合が複雑になる。PRD は wav チャンクを前提にしている |
| メインプロセスで録音する | Electron のメインプロセスにマイクを読む標準 API がなく、ネイティブアドオンか外部ヘルパーが必要になる |
| Swift の AVAudioEngine ヘルパーで録音する | 録音の安定性は高いが、ネイティブコードのビルドと署名が増える。システム音声は BlackHole 2ch で取得するため、録音全体をネイティブにする理由がない |
| 1 本の WAV に連続して書く | 実装は単純だが、異常終了でファイル全体を失う。R-5 を満たせない |
| 30 秒や 60 秒のチャンクにする | 書き込み回数は減るが、異常終了時に失う音声が長くなる。PRD は 10 秒を指定している |
| Renderer から File System Access API で直接書く | Electron の Renderer で任意のパスに書く権限を持たせにくく、IPC でメインプロセスに渡すほうが権限を絞れる |
| 録音を複数同時に走らせる | CPU とディスクの競合が増え、入力ソースの選択も曖昧になる。会議の録音は 1 件ずつで足りる |

## 結果

- 48 kHz、16-bit PCM、モノラルのチャンクは 1 時間で約 345 MB になる。
  16 kHz の wav は 1 時間で約 115 MB、mp3 は 64 kbps で約 29 MB になる。
  録音中の空き容量を確認し、停止後に不要なチャンクと wav を削除する必要がある。
- 異常終了時に失うのは、最後に確定していない 10 秒未満の音声だけになる。
  復旧処理は、残ったチャンクを結合し、文字起こしとエンコードをやり直す形にする。
- Renderer がクラッシュすると録音が止まる。
  メインプロセスは Renderer のクラッシュを検知し、録音状態と最後のチャンクを `meta.json` に残す。
- マイクとシステム音声を同時に録るとき、2 つのストリームのクロックが完全には一致しない。
  長時間の録音でずれが蓄積する可能性があるため、同時録音の試験で確認する。
- 60 分の連続録音で、マイク入力のピークが 1.0 に達した。
  入力レベルが 1.0 に近い場合はクリッピング警告を出し、ゲイン調整を案内する必要がある。
- システム音声の出力先が録音中に変わると、BlackHole は無音のフレームを返し続ける。
  直近の入力レベルが一定時間 0 なら、システム音声が届いていない旨を警告する必要がある。
- 180 秒のテストでシステムスリープを 19 秒発生させた。
  復帰後は取得を再開したが、スリープ中の音声は欠落するため、録音中は `powerSaveBlocker` を有効にする必要がある。
- 10 秒ごとの IPC とファイル書き込みが録音中の負荷になる。
  PCM の 16-bit 変換の場所は実装時に決めるが、ファイル書き込みはメインプロセスで行い、Renderer では AudioWorklet の処理だけに留める。
- 入力デバイスを録音中に抜き差しした場合の挙動を決める必要がある。
  デバイスが消えたら録音を継続できないため、警告を出して停止するか、代替のデバイスに切り替えるかを実装時に決める。
- 画面を閉じても録音を続けるには、メインプロセスと録音用の Renderer を生かしておく必要がある。
  メインウィンドウを閉じたときの挙動は ADR-0012 で決める。

## 未決事項

- 入力デバイスが 16-bit PCM 以外の形式を返す場合の変換方法。
  44.1 kHz の入力はそのまま保存し、ffmpeg で変換する。
- Float32 の PCM を 16-bit PCM に変換する処理を、Renderer とメインプロセスのどちらで行うか。
- 録音中の画面ロック、ディスプレイスリープ、スクリーンセーバーの挙動と、その間の音声取得の可否。
- 無音警告を出すまでの秒数と、警告の出し方。
- システム音声の無音検出の閾値と、出力先が変わったときの警告の文言。
- クリッピング警告を出す閾値と、マイクのゲイン調整の方法。
- マイクとシステム音声を同時に録るときのクロックずれの補正方法。
- 録音中の空き容量の下限と、空き容量が不足したときの停止手順。
- 録音中の入力デバイス変更を許可するか、録音停止後にだけ変更できるようにするか。
- 異常終了後の復旧を自動で行うか、ユーザーに確認してから行うか。
- 一時ディレクトリの WAV を録音中に暗号化するか。
  PRD は録音データの暗号化を求めていないため、MVP では平文とする想定である。
