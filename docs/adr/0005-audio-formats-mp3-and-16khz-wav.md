# ADR-0005: 保存音声は mp3 64 kbps（設定で 128 kbps）、文字起こし入力は 16 kHz モノラル WAV とする

Created: 2026-10-28
Model: DeepSeek V4.1 Flash 1017
Status: Accepted

## 背景

Kataribe は、録音した会議音声を mp3 として保存し、文字起こし用に 16 kHz の wav を生成する（PRD の R-4）。
mp3 は保存と再生のための形式で、設定により 64 kbps から 128 kbps に変更できる。
16 kHz wav は whisper.cpp の入力に使う一時ファイルで、文字起こしが完了したら削除する。
再文字起こしをするときは、mp3 から 16 kHz wav を作り直す。

録音のチャンクは、入力のサンプルレート、16-bit PCM、モノラルの WAV として保存する（ADR-0002）。
停止後にチャンクを結合し、mp3 と 16 kHz wav を ffmpeg で作る（ADR-0004）。
最初の文字起こしでは、mp3 を経由せず、結合した PCM から 16 kHz wav を作る。
mp3 は非可逆圧縮なので、mp3 から作り直した wav は最初の wav より情報が少なくなる。

会議の音声は人の発話が中心で、音楽的な品質は求めない。
ファイルサイズ、macOS での再生互換性、文字起こしの入力品質のバランスを決める必要がある。

## 決定

- 保存用の音声は `audio.mp3` とする。
  形式は MP3、モノラル、サンプルレートは 44.1 kHz、ビットレートは既定で 64 kbps とする。
  設定画面で 128 kbps に変更できる。
  ビットレートの設定は新しく録音する会議に適用し、既存のファイルは変更しない。
- 文字起こし用の音声は `audio.16k.wav` とする。
  形式は WAV、16 kHz、モノラル、16-bit PCM とする。
- 強調を OFF にした最初の文字起こしでは、録音チャンクを結合した PCM から `audio.16k.wav` を作る。
  mp3 を経由しない。
- 再文字起こしでは、`audio.mp3` から `audio.16k.wav` を作り直す。
  再文字起こしの画面には、元の mp3 から wav を作り直す旨を表示する。
- 文字起こし前の強調を ON にした比較セッションでは、`audio.mp3` から `audio.16k.wav` を作り、生と強調の比較に使う。
  PCM から作った `audio.16k.wav` は比較セッションでは作らない。
- `audio.16k.wav` は、文字起こしが成功したら削除する。
  文字起こしが失敗した場合、キャンセルされた場合、タイムアウトした場合は、再試行のために残す。
  比較セッションでは、生と強調のどちらかの文字起こしが失敗、キャンセル、タイムアウトした場合も残す。
- 録音チャンクの `chunks/` は、mp3 と 16 kHz wav の生成が成功したら削除する。
  生成に失敗した場合は、復旧のために残す。
- 音声の変換は ffmpeg の `libmp3lame` と PCM の変換機能で行う。
  mp3 の書き出しと 16 kHz wav の生成は、それぞれ別の ffmpeg の実行として扱う。
- モノラルへの変換では、入力がステレオの場合に左右のチャンネルを平均する。
  マイクとシステム音声を同時に録るときは、混合後の信号をモノラルにする（ADR-0002）。
- 生の音声ファイルの名前は `audio.mp3` と `audio.16k.wav` に固定する。
  会議のタイトルや日付はフォルダ名と `meta.json` に持たせ、音声ファイル名には入れない。
- 録音停止後の保存音声の強調を ON にした会議では、派生音声として `audio.enhanced.nemotronlabs.mp3` を追加する (ADR-0027)。
  生の `audio.mp3` を正とし、`audio.enhanced.nemotronlabs.mp3` は派生ファイルとして扱う。
  再実行は一時ファイルに書き、成功したときだけ既存の強調 mp3 を置き換える。失敗したときは以前の強調 mp3 を残す。
- 音声強調は、入力のサンプルレートを保った 16-bit PCM モノラルの WAV を出力する。
  ステレオの入力は左右を平均してモノラルにする。
  強調の入力と出力は一時ファイルに置き、成功、失敗、キャンセルのいずれでも削除する。
- 音声ファイルに ID3 タグは付けない。
  会議の情報は `meta.json` と `transcript.md`、`summary.md` の front matter に持たせる。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| M4A や AAC で保存する | 圧縮効率はよいが、PRD が mp3 を指定している。macOS 以外の環境に持ち出したときの互換性も mp3 のほうが広い |
| Opus で保存する | 低ビットレートの音声品質はよいが、Finder や一般的な音声プレイヤーでの対応が mp3 ほど広くない。会議の保存形式としては mp3 で足りる |
| FLAC で保存する | 非可逆圧縮の劣化は避けられるが、ファイルサイズが大きくなる。会議の保存と共有には mp3 で足りる |
| WAV だけで保存する | 1 時間で数百 MB になり、会議フォルダを Obsidian や Git に置く用途に合わない |
| 既定を 128 kbps にする | 64 kbps でも人の発話には十分で、ファイルサイズを半分にできる。128 kbps は設定で選べるようにする |
| mp3 から直接文字起こしする | ffmpeg の変換を 1 回減らせるが、非可逆圧縮の劣化が文字起こしの精度に影響する。最初の文字起こしは PCM から作る |
| 16 kHz wav を文字起こし後も残す | 再文字起こしのたびに mp3 から作る必要はなくなるが、1 時間で約 115 MB を会議ごとに残すことになる。PRD は完了後の削除を求めている |
| ステレオのまま保存する | 会議の聞き取りにはモノラルで十分で、ファイルサイズが倍になる。話者分離を入れる段階で再検討する |

## 結果

- 64 kbps の mp3 は 1 時間で約 29 MB、128 kbps では約 58 MB になる。
  16 kHz、16-bit PCM の wav は 1 時間で約 115 MB になる。
  録音中はチャンクの約 345 MB を Application Support のボリュームで、mp3 と 16 kHz wav を保存先のボリュームで確認する。
- 再文字起こしでは、最初の文字起こしより精度が下がる可能性がある。
  画面にはその旨を表示する。
- mp3 は Chromium の音声プレイヤーで再生できるため、アプリ内の再生に追加のコーデックを必要としない。
- 44.1 kHz の mp3 は、macOS の標準的なプレイヤーと外部のツールで扱いやすい。
  16 kHz wav は whisper.cpp の入力に合わせた形式で、他の用途には使わない。
- モノラルに混合すると、話者の位置や左右の定位は失われる。
  話者分離を入れる段階では、ステレオの入力と保存を別途検討する。
- 音声の混合時にクリッピングが起きる可能性がある。
  マイクとシステム音声のゲインを調整し、必要ならリミッターを入れる。
- ffmpeg の mp3 エンコーダのビルドに `libmp3lame` が必要になる。
  同梱バイナリのライセンスとビルド構成は ADR-0004 で扱う。

## 未決事項

- 将来、mp3 のサンプルレートを 48 kHz に変更するか。
  48 kHz の入力デバイスが多いため、変換の回数を減らす目的で検討する。
- 128 kbps の設定を会議ごとに上書きできるようにするか、アプリ全体の設定だけにするか。
- マイクとシステム音声の混合時のゲインとリミッターの設定。
- ID3 タグを将来付けるか。
  付ける場合は、タイトル、録音日時、会議の長さをどの項目に載せるか。
- ステレオのまま保存する選択肢を、話者分離の実装時に復活させるか。
