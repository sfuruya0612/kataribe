# ADR-0010: 会議データはフォルダを正本とし、SQLite を再構築可能な索引にする

Created: 2026-10-28
Model: DeepSeek V4.1 Flash 1017
Status: Accepted

## 背景

Kataribe は、会議 1 件を 1 つのフォルダにまとめ、mp3、文字起こし、要約、メタデータを保存する（PRD の F-1）。
保存先のルートは設定画面で変更でき、Obsidian の Vault なども指定できる（PRD の F-2）。
会議一覧は日付順に表示し、タイトルを編集できる（PRD の F-3）。
文字起こしと要約の全文検索は次フェーズの機能だが、PRD のデータ設計には SQLite と FTS5 が挙げられている。

コアバリューは、成果物がプレーンなファイルとして手元に残り、Obsidian や Git にそのまま取り込めることにある。
アプリを削除しても、フォルダをコピーすれば内容を読める必要がある。
一方で、会議の件数が増えると、毎回すべてのフォルダを走査して一覧を作るのは遅くなる。
全文検索には、Markdown をそのまま走査する以外の索引が要る。

ファイルを正本にすると、外部のエディタで Markdown を編集できる。
その代わり、ファイルと索引の内容がずれる可能性がある。
索引を削除してもフォルダから再構築できることを、設計の前提にする。

## 決定

- 会議 1 件は 1 つのフォルダとする。
  保存先のルートの下に `YYYY/YYYY-MM-DD_HHMM_<タイトル>/` を作る。
  タイトルが未入力の場合は `タイトル未入力` を使う。
- `meta.json` に会議 ID の UUID を持ち、一時ディレクトリと索引のキーに使う。
  フォルダ名を変更しても、会議 ID は変えない。
- 会議フォルダには次の最終成果物を置く。
  - `audio.mp3`: 保存用の音声。
  - `transcript.md`: タイムスタンプ付きの文字起こし（ADR-0011）。
  - `summary.md`: 要約、決定事項、ToDo、未決事項（ADR-0011）。
  - `meta.json`: 録音条件、処理状況、使用モデル、使用プロバイダを持つメタデータ。
- 音声強調を使った会議では、次のファイルを追加する (ADR-0027)。
  - 会議フォルダの成果物:
    - `audio.enhanced.nemotronlabs.mp3`: 商用利用が可能なモデルで強調した保存音声。生の `audio.mp3` は残す。
    - `transcript.raw.md` と `transcript.nemotronlabs.md`: 強調前と強調後の比較用文字起こし。`transcript.md` を要約、翻訳、検索の正とし、ToDo は `summary.md` を正とする。
    - `transcript.previous.md`: 文字起こし前の強調の再実行前のコピー。
  - 正本:
    - `enhancement.json`: 音声強調の状態の正本。設定、モデル、処理時間、入出力のハッシュを持つ。
  - tmp の一時ファイル:
    - `audio.16k.enhanced.wav`: 文字起こし前の強調 WAV。保存先ルートの外の tmp に置き、成功、失敗、キャンセルで削除する。
- 録音中の `chunks/`、文字起こし用の `audio.16k.wav`、mp3 からデコードした一時 WAV は、保存先ルートの外の `~/Library/Application Support/Kataribe/tmp/<meeting-id>/` に置く。
  `chunks/` の削除は ADR-0005 に従う。
  文字起こし用の `audio.16k.wav` は ADR-0005 に従い、文字起こしが失敗、キャンセル、タイムアウトしたときは再試行のために残す。
  mp3 からデコードした一時 WAV は、成功、失敗、キャンセルのいずれでも削除する。
  起動時に、復旧データを持たない会議の一時ディレクトリを削除する。`status` が `error` の会議、または `transcription.state` が `partial`、`failed`、`cancelled`、`interrupted` の会議は、`chunks/` と `audio.16k.wav` を残す。比較セッションの生と強調のどちらかが完了していない会議も残す。
  これにより、保存先がクラウド同期の対象でも、録音中の音声と一時 wav が同期されない。
- 録音チャンクを結合した `audio.wav` は、処理中だけ会議フォルダに置き、保存音声の強調と、OFF のときの 16 kHz WAV の生成後に削除する。
  保存先がクラウド同期の対象の場合、処理中は `audio.wav` が同期され得る。
- `enhancement.json` を音声強調の状態の正本とし、`meta.json` は会議一覧に必要な状態の要約だけを持つ。
- 音声強調モデルの重みは、アプリに同梱せず、`~/Library/Application Support/Kataribe/models/reuse/nemotronlabs.safetensors` に置く。
  初回利用時に Hugging Face から HTTPS でダウンロードし、SHA-256 を照合してから使う。
  会議フォルダには置かない。
- ファイルを会議データの **正本** とする。
  `meta.json`、`transcript.md`、`summary.md`、`diarization.json`、`enhancement.json` の内容が正であり、SQLite はそこから作る索引である。
  SQLite を削除しても、会議フォルダから索引を再構築できる。
- 索引の SQLite ファイルは、保存先ルートの直下ではなく、`~/Library/Application Support/Kataribe/index/<保存先ルートのハッシュ>.sqlite` に置く。
  SQLite をクラウド同期の対象にしないためである。
  PRD のデータ設計の索引の位置を、Application Support に変更する。
- MVP では SQLite を導入する。
  SQLite は会議一覧の高速化に使い、全文検索の FTS5 は次フェーズで同じファイルに追加する。
- SQLite は、会議の本文、タイトル、状態の正本にはしない。
  索引のテーブルは、会議 ID の UUID を主キーとし、会議フォルダのパス、タイトル、日付、長さ、状態、更新日時を持つ。
  全文検索用の FTS5 のテーブルは、文字起こしと要約の本文を持つ。
- SQLite の索引は、アプリの起動時と、会議フォルダの変更を検知したときに更新する。
  索引の再構築のコマンドを設定画面か開発用のメニューに用意する。
- `meta.json` は JSON で書き、`schema_version`、`id`、`status`、`title`、`started_at`、`duration`、`source`、`model`、`provider`、各段階の開始と終了の時刻を持つ。
  `status` は `recording`、`encoding`、`enhancing`、`transcribing`、`transcribed`、`summarized`、`error` のいずれかとする (PRD のデータ設計)。
  録音の最終チャンク番号、期待する総サンプル数、サンプルレート（ADR-0002）、文字起こしの状態、部分結果、再開回数（ADR-0007）、アプリのバージョン（ADR-0014）も同じファイルに持つ。
- `meta.json`、`transcript.md`、`summary.md`、`enhancement.json` の書き込みは、一時ファイルに対して行ってから rename する。
  途中の書き込みでファイルが壊れないようにする。
  JSON は書き込み前に schema を検査する。
- `meta.json` の `title` を会議タイトルの正とする。
  フォルダ名と `transcript.md`、`summary.md` の front matter は `meta.json` から更新する。
  外部のエディタで front matter の `title` を変えた場合は、`meta.json` を優先し、次回の保存で front matter を戻す。
- タイトルを変更したら、会議フォルダの名前も変更する。
  録音、エンコード、文字起こし、要約のジョブが会議フォルダを使用している間は改名を保留し、すべてのジョブが終わってから変更する。
- タイトルは NFC に正規化し、ファイル名に使えない文字を除き、UTF-8 で 120 バイト程度に切り詰める。
  `.` と `..`、macOS の予約名を拒否し、大文字小文字を無視して重複する場合は連番を付ける。
- 外部のエディタで `transcript.md` や `summary.md` が編集されることを許す。
  アプリはファイルの更新日時と内容のハッシュを見て、索引を更新する。
  アプリ内の編集も同じファイルに書き、別の形式のデータベースを持たない。
- 保存先ルートが iCloud Drive、Dropbox、OneDrive、Google Drive、既知の Obsidian の同期フォルダなどに含まれる場合、音声と文字起こしが端末外に同期される。
  初回設定時と保存先の変更時に検出し、警告と明示的な確認を出す。
  同期対象のルートを選ぶ場合は、音声を同期するか、同期しない設定にするかを利用者に選ばせる。
- 会議フォルダとファイルは、フォルダを 0700、ファイルを 0600 で作成し、作成後に chmod して umask の影響を除く。
  保存先のルートの外にファイルを書かないよう、タイトルから組み立てたパスを検査する。
- 会議を削除したら、会議フォルダと SQLite の索引の行を削除する。
  FTS5 の行も削除し、必要なら `VACUUM` する。
- 起動時に `PRAGMA quick_check` を実行し、SQLite の破損を検出したら DB を退避して会議フォルダから再構築する。
  再構築はメインスレッドをブロックしないよう、バックグラウンドで少しずつ行う。
- 保存先のルートを変更しても、既存の会議フォルダは移動しない。
  変更前に、既存の会議が新しい一覧に表示されないことを警告し、旧ルートを追加のライブラリとして登録するか、移行するかを選ばせる。
- アプリのインスタンスは 1 つに制限する。
  複数のプロセスが同じ SQLite と会議フォルダを同時に更新しないようにする。
- バックアップは、保存先のフォルダをコピーするか、Time Machine に任せる。
  SQLite は再構築できるため、バックアップの必須の対象にはしない。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| SQLite を正本にする | 一覧と検索は速くなるが、フォルダをコピーしただけでは内容を読めず、Obsidian や Git に取り込むというコアバリューに反する |
| 毎回すべてのフォルダを走査する | 会議が増えると一覧の表示が遅くなり、全文検索も現実的でない。SQLite の索引を置く理由がなくなる |
| クラウドのデータベースに保存する | 音声と文字起こしを端末内に置く方針に反する（ADR-0013） |
| 会議ごとに 1 つのアーカイブファイルにする | 中身が見えず、外部のエディタで開けない。Git の差分も読めない |
| Obsidian の Vault の構造に合わせて保存する | Obsidian 依存の構造になり、他の用途に移しにくい。会議フォルダの規則はアプリ側で持つ |
| メタデータを SQLite にだけ持つ | SQLite が壊れたときに会議の状態を失う。meta.json を正本にする |
| JSON の索引ファイルを持つ | 全文検索の機能を自前で作ることになり、FTS5 の利点を失う |
| タイトルをフォルダ名に反映しない | 利用者が Finder から会議を探しにくい。PRD はタイトル変更時の改名を求めている |

## 結果

- 会議フォルダをコピーすれば、別の Mac や Obsidian の Vault にそのまま移せる。
  SQLite の索引は移行先で再構築する。
- 外部のエディタで Markdown を編集できる。
  アプリは編集を検知して索引を更新するが、同時に編集した場合の競合の扱いを決める必要がある。
- 最終成果物の `audio.mp3`、`transcript.md`、`summary.md` は保存先ルートに置くため、同期対象のルートを選ぶとクラウドに出る。
- 索引が壊れても、会議フォルダから再構築できる。
  起動時の `PRAGMA quick_check` で破損を検出し、再構築の時間は会議の件数に比例する。
- 実装では Electron に含まれる Node.js の `node:sqlite` を使う。
  `better-sqlite3` のようなネイティブモジュールの再ビルドは不要になった。
  FTS5 の trigram トークナイザーは、Electron 45 の `node:sqlite` で動作を確認した。
  配布ビルドに含める際の署名と公証も確認する。
- FTS5 の既定のトークナイザーは日本語の単語分割に適さない。
  trigram を使う場合は 3 文字未満の検索に制約があるため、2 文字検索の扱いを別に決める必要がある。
- タイトルの変更でフォルダ名を変えると、外部のツールが持つパスのリンクが切れる可能性がある。
  索引は会議 ID で同一性を保つため、変更前のパスを残す必要はない。
  外部ツールのリンク切れをどう扱うかを決める。
- 会議フォルダの権限を制限することで、他の利用者から内容を読みにくくする。
  macOS の FileVault が有効であれば、ディスク全体の暗号化も効く。
- 単一インスタンスに制限することで、SQLite のロックとフォルダの同時更新を避ける。
  Electron の `requestSingleInstanceLock` を使う。
- 保存先のルートを変更すると、旧ルートの会議は新しい一覧に表示されない。
  変更時に警告を出し、旧ルートを追加のライブラリとして登録するか、既存のフォルダを移行するかを利用者が選ぶ。

## 未決事項

- FTS5 を次フェーズで追加するときの移行と再構築の手順。
- 日本語の全文検索に使う FTS5 のトークナイザーと、2 文字検索の扱い、検索のランキング。
- タイトルからフォルダ名を作るときの文字の除去規則と、重複したときの連番の付け方。
- 外部のエディタとの同時編集の競合をどう扱うか。
  アプリ側の変更を優先するか、ファイルの更新日時で検出するか。
- iCloud Drive や Dropbox の同期フォルダを保存先にした場合の、競合とロックの扱い。
- `meta.json` の schema のバージョンと移行方法。
- 保存先のルートを変更したとき、将来、既存のフォルダを移動する機能を入れるか。
- 会議フォルダを暗号化するか。
  PRD は暗号化を求めていないが、会議の内容の機密性に応じて検討する。
- SQLite の WAL モードを使うか、ジャーナルモードにするか。
- 索引に含める項目と、検索の対象にするファイル。
- 会議の件数の上限と、索引の再構築にかかる時間の目標。
