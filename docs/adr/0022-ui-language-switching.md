# ADR-0022: UI の表示言語を日本語と英語で切り替える

Created: 2026-11-01
Model: DeepSeek V4.1 Flash 1017
Status: Accepted

## 背景

画面、トレイメニュー、アプリケーションメニュー、確認ダイアログ、進捗メッセージ、エラーメッセージの文言は日本語で直書きしている。
利用者が英語環境でアプリを確認するときや、英語話者へ画面を共有するときに、表示言語を切り替えたい。
保存済みの会議データは利用者の成果物であり、表示言語の切り替えで内容を書き換えると、検索、要約、共有の前提が崩れる。

## 決定

- `AppSettings.uiLanguage` を `'ja' | 'en'` で追加し、既定を `'ja'` とする。設定の保存と復元は `SettingsStore` が担う。
- 日本語の原文をキーにした英語の辞書を `src/shared/i18n.ts` に置く。Renderer と main プロセスは同じ辞書を使う。
- Renderer は React の context で現在の言語とメッセージ関数を配る。main プロセスは `SettingsStore` の値を `src/main/i18n.ts` の言語へ同期し、`t` で文言を返す。
- Renderer は preload 経由で現在の UI 言語を取得してから初回描画する。保存した言語と異なる言語で一瞬描画されることを避けるため。
- 表示言語は、画面の固定文言、トレイメニュー、アプリケーションメニュー、確認ダイアログ、進捗メッセージ、新しく生成するエラーメッセージに適用する。
- 会議のタイトル、文字起こし、翻訳、要約、話者名、会議フォルダ名、LLM のプロンプトは翻訳しない。保存済みのメッセージは生成時の言語を保つ。
- 言語の変更時は、アプリケーションメニューとトレイメニューを組み直し、Renderer の context を更新する。
- 検索結果の種別名は main プロセスで生成せず、Renderer が検索種別から表示名を選ぶ。
- 新しい依存は追加しない。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| i18next などの外部ライブラリを追加する | 対応言語が 2 つで、依存を増やす利点が小さい |
| キー名の辞書を使う | キー名と原文の対応を二重に保守する必要があり、原文を変えたときの翻訳漏れを型で検出しにくい |
| 保存済みの会議データも翻訳する | 利用者の成果物を表示言語の切り替えで書き換え、検索と共有の前提が崩れる |

## 結果

- 利用者は再起動なしで表示言語を切り替えられる。
- 日本語の原文を変更すると、英語の辞書の更新漏れを型検査が検出する。
- 同じ日本語の原文を複数の文脈で使う場合、英語の訳語を文脈ごとに変えられない。訳語を変えるときは原文を書き分ける。
- 保存済みの会議データと過去のエラーメッセージは、表示言語を切り替えても元の言語のまま残る。
- 英語 UI で新しく録音した会議も、既定タイトルと会議フォルダ名は「タイトル未入力」のままとする。これらは保存データであり、表示言語の切り替え対象にしない。
- 日付の表記は表示言語に合わせる。数値の桁区切りは日本語と英語で同じ形式を使う。
- 翻訳の品質は辞書の保守に依存する。新しい画面文言を追加するときは、同じ変更で英語の辞書も更新する。
