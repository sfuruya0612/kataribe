# ADR-0023: ToDo 一覧は要約 Markdown のチェックボックスを正本にする

Created: 2026-11-01
Model: DeepSeek V4.1 Flash 1017
Status: Accepted

## 背景

Kataribe の要約は `summary.md` に保存し、ToDo はチェックボックス付きの行として持つ (ADR-0011)。利用者はこのチェックボックスを Obsidian などの外部エディタで操作できる。

会議ごとの要約に埋もれている ToDo を、会議をまたいで確認したい需要がある。一方で、完了状態を保存する場所として、`summary.md` のチェックボックス、`meta.json`、SQLite の検索索引が候補になる。`summary.md` の本文は利用者が編集でき、検索索引は会議フォルダから再構築する派生物である。

要約の再生成は、既存の `summary.md` を `summary.previous.md` に退避したうえで、新しい本文で上書きする (ADR-0011)。完了状態をチェックボックスに保存すると、再生成のたびに状態が失われる。

## 決定

- ToDo 一覧は、各会議の `summary.md` の ToDo セクションにあるチェックボックス行を読んで組み立てる。SQLite の索引に ToDo 専用のテーブルや完了状態の列を追加しない。
- 完了状態の正本は `summary.md` のチェックボックスとする。`meta.json` と SQLite 索引に完了状態を複製しない。
- 一覧のチェック操作は、対象の `summary.md` を読み直し、指定された行番号の行がチェックボックスであり、本文が一覧の本文と一致するときだけ、`[ ]` と `[x]` の 1 文字を書き換える。一致しないときは書き込みを拒否する。
- 一覧の取得は、会議一覧と同じ順序 (Pin 止め、会議の開始日時の降順) で各会議の `summary.md` を読む。要約がない会議と ToDo がない会議は一覧に含めない。
- 未完了、完了、すべての表示切り替えと会議ごとのグルーピングは Renderer が行う。UI の固定文言は日本語と英語の辞書に従い、ToDo の本文は翻訳しない (ADR-0022)。
- 要約を再生成するとき、アプリは既存の要約を上書きすることと、ToDo の完了状態を引き継がないことを、送信前の確認ダイアログに表示する。
- 再生成時に ToDo の対応付けと完了状態の引き継ぎを行わない。LLM が ToDo の表現を変えるため、本文の一致による対応付けは誤りやすい。
- 新しい依存を追加しない。

## 結果

- アプリと Obsidian などの外部エディタが同じ完了状態を共有できる。
- 検索索引を再構築しても完了状態は失われない。索引は検索用の派生物のままになる。
- 要約を再生成すると完了状態は失われる。アプリは送信前に警告するが、失った状態を自動で復元する手段は提供しない。
- 外部エディタで `summary.md` の行を挿入すると、一覧が保持する行番号と本文がずれる。アプリは本文の一致を確認して書き込みを拒否するため、利用者は一覧を再読み込みする。
- 会議の数に比例して `summary.md` を読むため、一覧を開くたびにファイルの読み取りが増える。会議数が増えて表示が遅くなった場合、索引に読み取り専用の派生データを持つかを実測で判断する。
- ToDo セクションがない要約と、チェックボックス以外の形式で書かれた行は一覧に表示しない。
