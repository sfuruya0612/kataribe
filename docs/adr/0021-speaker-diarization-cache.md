# ADR-0021: 話者分離の結果をキャッシュして話者名を保持する

Created: 2026-11-01
Model: DeepSeek V4.1 Flash 1017
Status: Accepted

## 背景

現在は、話者分離が有効なとき、文字起こしが完了するたびに話者分離の CLI を実行する。
再文字起こしは `transcript.md` を作り直し、`meta.speakers` を新しい自動ラベルで上書きする。
同じ音声と同じ話者分離設定でも、60 分の音声に約 4 分の分離処理を繰り返す。
利用者が付けた話者名は再文字起こしで失われ、付け直しが必要になる。
ADR-0020 は、再文字起こしで話者ラベルが自動ラベルに戻ると記録している。
話者分離の生ターンは音声と分離設定だけで決まり、whisper のセグメントとは独立である。

## 決定

- 話者分離の生ターンと、クラスタ ID ごとの話者名を、会議フォルダの `diarization.json` に保存する。
- 音声ハッシュは、再生成される 16 kHz WAV ではなく、保存済みの audio.mp3 を使う。最初の文字起こしと再文字起こしで同じ音声を参照するため。
- キャッシュキーは、キャッシュ形式のバージョン、会議の audio.mp3 の SHA-256、セグメンテーションモデルの SHA-256、話者埋め込みモデルの SHA-256、話者数設定、クラスタ閾値、実行スレッド数とする。
- whisper のモデルと文字起こしセグメントはキャッシュキーに含めない。ターンを新しいセグメントに再割り当てできるためである。
- キャッシュが一致するときは CLI を起動せず、保存済みターンを新しいセグメントに再割り当てする。
- クラスタ ID に話者名があればその名前を、なければ自動ラベルを使う。話者名はクラスタ ID で保持し、自動ラベルの順序が変わっても維持する。
- `diarization.json` の `names` は、現在のターンが参照するクラスタだけを対象にする。文字起こしに現れないクラスタの名前を残すと、後の改名で表示名が重複し、キャッシュが不正になるため。読み込みと書き込みの両方で、`names` のキーが `labels` の値に含まれることを検証する。
- キャッシュが一致しないときは CLI を実行し、生ターンとクラスタ ID ごとの話者名を更新する。音声、分離モデル、話者数、閾値、スレッド数が変わった場合は話者名を自動ラベルに戻す。
- `diarization.json` をクラスタ ID と話者名の正とする。`meta.speakers` は既存会議の読み取りにだけ使い、現在の表示名のスナップショットとして更新する。
- 会議詳細の話者名の変更は、`transcript.md` と翻訳を書き換えるのと同じ操作で、`diarization.json` のクラスタ ID の話者名を更新する。
- 再文字起こしでキャッシュを使ったときは、既存の翻訳の話者ラベルを、変更前の表示名から変更後の表示名へ置き換える。話者名を保持していない行は変更しない。
- キャッシュの読み込みに失敗した場合と、内容が不正な場合は、キャッシュを無視して CLI を実行する。書き込みに失敗した場合はログに残し、文字起こしと話者分離は完了させる。古いキャッシュが残らないよう `diarization.json` を削除し、次回の文字起こしで作り直す。
- 部分文字起こし、失敗、キャンセルのときは `diarization.json` を削除しない。次に文字起こしが完了したときに再利用する。
- 会議フォルダを削除すると `diarization.json` も削除される。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| 現在のとおり毎回 CLI を実行する | 同じ音声でも約 4 分を繰り返し、話者名も失われる |
| 文字起こしに話者ラベルがあればスキップする | 新しい文字起こしのセグメントと古いラベルの対応が保証されず、誤った話者を付ける |
| 話者名を transcript.md の front matter に保存する | 話者名は保持できるが、分離処理の再利用にならず、Markdown の形式も変わる |
| キャッシュを Application Support に置く | 会議フォルダをコピーしたときに話者名が移らず、フォルダ単体で完結しない |
| キャッシュを meta.json に置く | ターンの配列で会議のメタデータが大きくなり、meta.json の役割が広がる |
| モデルが変わってもクラスタ ID の話者名を引き継ぐ | クラスタ ID の対応が保証できず、別人に名前を付ける可能性がある |

## 結果

- 同じ音声と同じ話者分離設定の再文字起こしでは、話者分離の CLI を実行せず、約 4 分を短縮できる。
- クラスタ ID に付けた話者名が再文字起こし後も残る。
- 会議の audio.mp3 の SHA-256 を計算するため、再文字起こしごとに mp3 の読み取りが増える。分離処理の短縮に比べて小さい。
- 最初の文字起こしでは元の WAV から 16 kHz WAV を作る場合があり、再文字起こしの mp3 由来の WAV と完全には一致しない。キャッシュは保存済みの audio.mp3 を同じ会議の音声として扱い、話者ターンを再利用する。
- `diarization.json` は会議フォルダに残る。ターン数が多い会議でも数百 KB 程度で、削除は会議フォルダの削除に含まれる。
- 音声、分離モデル、話者数、閾値、スレッド数が変わるとキャッシュが無効になり、話者名は自動ラベルに戻る。
- 翻訳の話者名は、キャッシュを使った再文字起こし時に置き換える。キャッシュを無効にした場合は、話者名が自動ラベルに戻るため、翻訳は自動で書き換えない。要約は自動で書き換えない。
- 手動で文字起こしの話者名を書き換えた場合は、キャッシュの話者名と一致しないことがある。対応する操作は会議詳細の話者名の変更に限定する。
- 話者分離だけを再実行する UI は、この決定の対象外とする。
