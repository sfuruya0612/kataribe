# ADR-0008: LLM 要約は OpenAI 互換 Chat Completions を共通プロトコルにし、プロバイダ差分をアダプタで吸収する

Created: 2026-10-28
Model: DeepSeek V4.1 Flash 1017
Status: Accepted

## 背景

Kataribe は、文字起こしを任意の LLM に送り、要約、決定事項、ToDo、未決事項の 4 セクションを持つ Markdown を生成する（PRD の S-4）。
LLM のプロバイダは、エンドポイント URL、API キー、モデル名の組で登録し、切り替えて使える（PRD の S-1）。
PRD は ChatGPT、Claude、Gemini、Ollama Cloud、Fireworks AI の 5 つをプリセットとして同梱する（PRD の S-8）。
プリセットにないプロバイダは、カスタムとして追加できる。

GitHub Models は 2026-07-30 に廃止された。
そのため、PRD の S-8 は 5 つのプリセットに更新された。
6 つ目のプリセットを追加する場合は、代替のプロバイダを決めてから PRD に反映する。

OpenAI、Gemini、Ollama Cloud、Fireworks AI は OpenAI 互換の Chat Completions 形式のエンドポイントを提供している。
Anthropic は認証ヘッダーとリクエストの形が OpenAI と異なる。
Anthropic は OpenAI SDK 互換の層も提供しているが、`response_format` などの差分があり、長期の本番利用向けではない。
GitHub Models API は OpenAI 互換だったが、2026-07-30 に廃止された。
すべてのプロバイダを個別の SDK で実装すると、依存が増え、リクエストと出力の扱いがばらつく。

要約の送信は、利用者が明示的に操作したときだけ行う（PRD の S-3）。
送信前に、送る内容と送信先を確認できるダイアログを出す。
長い文字起こしは分割して送り、結果を結合する（PRD の S-6）。
出力言語は既定で日本語とし、設定と会議ごとの上書きを許す（PRD の S-9）。
60 分会議の文字起こしから要約生成まで 60 秒以内を目標とする（PRD の「非機能要件」）。

## 決定

- LLM の共通インターフェースを `ChatCompletionsClient` とする。
  リクエストは、エンドポイント URL、API キー、モデル名、システムプロンプト、ユーザープロンプト、温度、最大トークン数を持つ。
  レスポンスは、生成されたテキスト、使用トークン数、プロバイダのエラー情報を持つ。
- 共通プロトコルは OpenAI 互換の Chat Completions とする。
  OpenAI、Gemini、Ollama Cloud、Fireworks AI は、共通の OpenAI 互換アダプタで扱う。
  Anthropic は、認証ヘッダー、リクエストの形、レスポンスの形の差分を専用アダプタで吸収する。
  Anthropic のアダプタは、`x-api-key`、`anthropic-version`、必須の `max_tokens`、トップレベルの `system` を使い、レスポンスの `content[]` を読む。
- プロバイダの設定は、表示名、種類（OpenAI 互換または Anthropic）、エンドポイント URL、API キー、モデル名、追加のヘッダーを持つ。
  PRD の 5 つのプリセットは、種類、エンドポイント URL、モデル名の初期値を提供する。
  利用者はプリセットの値を編集でき、カスタムのプロバイダも追加できる。
- API キーは safeStorage で保存する（ADR-0009）。
  設定ファイルとログに平文の API キーを残さない。
- 送信前に確認ダイアログを出し、プロバイダ名、モデル名、エンドポイントの完全な URL、送る文字起こしの全文またはスクロール可能なプレビュー、文字数、概算のトークン数と料金を表示する。
  利用者が確認したときだけリクエストを送る。
  自動送信、バックグラウンド送信、定期的な送信は行わない。
- 送信の確認はメインプロセスのダイアログで行い、Renderer からは確認済みのワンタイムトークンだけを受け取る。
  API キーはプロバイダ ID とキー入力時のホストに束縛し、ホストが変わったら再入力を要求する（ADR-0009）。
- リクエストは `AbortController` でキャンセルできるようにする。
  接続、ヘッダー、本文、全体にタイムアウトを設ける。
  通信には Electron の `net.fetch` を使い、macOS のシステムプロキシと証明書を利用する。
- リクエストは MVP では非ストリーミングとする。
  画面には送信中であることと経過時間を表示し、完了したら結果を表示する。
  ストリーミングは、長い応答の待ち時間を短くする必要が出た段階で検討する。
- 出力は「要約」「決定事項」「ToDo」「未決事項」の 4 つの H2 セクションを持つ Markdown とする。
  プロンプトでこの形式を指定し、レスポンスを受け取ったらセクションの見出しを検査する。
  見出しが欠けている場合は、ADR-0011 に従って足りない見出しを空のセクションとして補い、元の出力は 4 つのセクションの後ろに残す。
  空のセクションも見出しだけ残す。
- 見出しの言語は、出力言語の設定に合わせる（ADR-0011）。
- 生成した要約はアプリ内で編集でき、同じ文字起こしから再生成できる（PRD の S-5）。
  再生成の前に既存の `summary.md` を退避し、上書きの確認を出す（ADR-0011）。
  再生成でも、LLM に送るのは文字起こしのテキストだけとする。
- ToDo は `- [ ]` で始まる行とし、担当と期限を括弧書きで含める。
  担当と期限が不明な場合は、推測で埋めずに、出力言語に合わせて「担当未定」「期限未定」または `Owner TBD`、`Due TBD` と書くようプロンプトで指示する。
- 出力言語は既定で日本語とする。
  設定で英語を選べるようにし、会議ごとに上書きできるようにする。
  言語の指定はシステムプロンプトに含める。
- 文字起こしは、モデルのコンテキスト長と概算のトークン数に基づいて、セグメントの区切りで分割して送る。
  分割が必要になる目安は、2 時間を超える会議とする。
  分割した結果は、最後に結合するための要約リクエストに渡す。
  分割の長さ、オーバーラップ、結合のプロンプトは実装時に決める。
- ネットワークエラー、HTTP 429、HTTP 5xx は指数バックオフで最大 3 回まで再試行する。
  HTTP 401、403、404、400 は再試行せず、設定の誤りとして画面に出す。
  再試行しても失敗した場合は、送信内容を保持したまま利用者に再実行を促す。
- リクエストがタイムアウトした場合と、接続が切れた場合は、別のエラーとして扱う。
- 文字起こしには、プロンプトインジェクションを避けるための区切りを付ける。
  文字起こしをデータとして扱い、その中の指示に従わないようシステムプロンプトで指示する。
  ただし、プロンプトインジェクションを完全には防げないものとして扱う。
- 送信するのは文字起こしのテキストだけとする。
  音声ファイル、会議フォルダのパス、API キー、その他のメタデータは送らない。
- リクエストとレスポンスの本文はログに残さない。
  ログにはプロバイダ名、モデル名、HTTP ステータス、所要時間、トークン数だけを残す。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| Vercel AI SDK などの抽象化ライブラリ | プロバイダの差分を吸収できるが、5 つのプリセットとカスタムの範囲では、依存のサイズと独自アダプタのテスト容易性を比べて利点が小さい。共通インターフェースは薄いアダプタで足りる |
| LangChain などのフレームワーク | 機能が多く、依存と学習コストが大きい。要約の 1 ユースケースには過剰である |
| プロバイダごとの公式 SDK | SDK ごとに認証、リクエスト、レスポンスの扱いが異なり、依存も増える。共通のインターフェースで揃えるほうがテストしやすい |
| OpenAI の Responses API を共通にする | Responses API を提供しないプロバイダがあり、5 つのプリセットを同じ実装で扱えない |
| ストリーミングを最初から入れる | 要約は 4 セクションの完了した Markdown を受け取ってから保存するため、途中の表示の利点が小さい。実装とテストが増える |
| ローカルの LLM だけを使う | 外部に送らない点は強いが、利用するモデルとハードウェアに品質が依存する。PRD は任意のプロバイダを求めている |
| プロバイダの API キーをアプリの設定ファイルに平文で置く | PRD の S-2 に反する。safeStorage を使う（ADR-0009） |
| 確認ダイアログを初回だけ出す | 送信先と内容は会議ごとに変わる。PRD は送信のたびに明示的な操作を求めている |

## 結果

- 5 つのプリセットとカスタムのプロバイダを、1 つの共通インターフェースで扱える。
  OpenAI 互換のプロバイダを追加するときは、設定を足すだけで済む。
- プロバイダの API は変更される。
  エンドポイント URL とモデル名はプリセットの初期値であり、利用者が編集できるようにして、アプリの更新なしで追随できるようにする。
- Anthropic のアダプタは、認証ヘッダー、メッセージの形、レスポンスの形を OpenAI と別に保つ。
  Anthropic の API が変わったときは、このアダプタだけを直す。
- 出力の 4 セクションを検査することで、LLM が形式を外したときに気付ける。
  検査に失敗した結果を捨てると利用者の待ち時間が無駄になるため、生の出力を残して編集させる。
- 長い文字起こしを分割すると、分割ごとの要約が全体の文脈を失う可能性がある。
  オーバーラップと結合のプロンプトで補うが、会議の決定事項が分割の境界をまたぐ場合の品質は保証できない。
- 非ストリーミングでは、60 秒の応答時間の目標に対して、画面は経過時間を出すだけになる。
  プロバイダの応答が遅い場合の待ち時間が長く感じられるため、進捗の表示を工夫する。
- 再試行は同じリクエストを複数回送る可能性がある。
  課金とレート制限に影響するため、再試行の回数と間隔をログに残す。
- プロンプトインジェクションのリスクは残る。
  文字起こしに含まれる指示を実行しないようプロンプトで指示するが、出力の内容は利用者が確認する。
- API キーと文字起こしをログに残さないことで、障害調査の情報は限られる。
  利用者にローカルのログを提供してもらい、再現する。

## 未決事項

- 将来、6 つ目のプリセットを追加するか。
  Azure AI Foundry、OpenRouter、GitHub Copilot の別 API などの候補から選び、PRD の S-8 を更新する。
- 5 つのプリセットのエンドポイント URL と既定のモデル名。
  提供元の仕様を確認し、実装時に固定する。
- ストリーミングを入れるか、入れないままにするか。
- 2 時間を超える文字起こしの分割の単位、オーバーラップの長さ、結合のプロンプト。
- トークン数の見積もり方法。
  プロバイダごとのトークナイザーを使うか、文字数からの概算にするか。
- 料金の概算に使う価格表の取得元と更新方法。
- リクエストのタイムアウト時間と、再試行の間隔。
- カスタムプロバイダで追加のヘッダーや組織 ID を設定できるようにするか。
- 4 セクションの検査と正規化の規則。
- 文字起こしの翻訳の詳細は ADR-0016 で扱う。
- モデル一覧をプロバイダの API から取得するか、利用者がモデル名を入力するか。
- プロンプトテンプレートの編集（PRD の S-7）を MVP の後に入れるか。
- プロバイダのデータ保持と学習の扱いを、確認ダイアログにどこまで表示するか。
