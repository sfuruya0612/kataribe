# ADR-0012: メニューバーに常駐し、メインウィンドウの 3 画面で会議を扱う

Created: 2026-10-28
Model: DeepSeek V4.1 Flash 1017
Status: Accepted

## 背景

Kataribe は、メニューバーまたはメインウィンドウから 1 クリックで録音を開始し、停止できる（PRD の R-1）。
入力ソースはマイク、システム音声、その両方から選び、録音中も現在の設定が見える（PRD の R-2）。
会議一覧は日付順に表示し、タイトルを編集できる（PRD の F-3）。
要約はワンクリックでクリップボードにコピーできる（PRD の F-4）。

PRD の画面構成は、メニューバー、会議一覧、会議詳細、設定の 4 つである。
メニューバーは常駐し、録音の開始と停止だけを素早く行う。
会議一覧は過去の会議と処理状況を見る。
会議詳細は音声を再生し、文字起こしと要約を編集する。
設定は保存先、モデル、LLM プロファイル、要約の出力言語を変更する画面である。
プロンプトテンプレートの編集は次フェーズに回す。

メニューバーとメインウィンドウの両方から録音を操作すると、状態の持ち主が曖昧になる。
録音の状態、経過時間、入力ソースを 1 か所で管理し、両方の画面に反映する必要がある。
メインウィンドウを閉じたときにアプリを終了するか、メニューバーに残すかも決める必要がある。

## 決定

- アプリはメニューバーに常駐する。
  Electron の `Tray` でアイコンを出し、メニューに録音の開始と停止、入力ソースの切り替え、経過時間、メインウィンドウを開く項目、終了を置く。
  トレイのアイコンをクリックすると録音を開始したり停止したりできるようにし、メニューは入力ソースの切り替えと終了に使う。
- メインウィンドウの画面は、会議一覧、会議詳細、設定の 3 つとする。
  メニューバーはウィンドウではなく、常駐する操作の入口として扱う。
- メインウィンドウを閉じたときは、アプリを終了せずにウィンドウを隠す。
  アプリの終了は、メニューバーの終了項目か macOS の終了操作で行う。
  MVP では、閉じる操作で終了する選択肢を設定に持たない。
- メインウィンドウは 1 つだけ作る。
  トレイから開いたときに既に開いている場合は、既存のウィンドウを前面に出す。
- 録音の状態、経過時間、入力ソース、文字起こしの進捗は、メインプロセスのジョブ管理に集約し、これを唯一の状態とする。
  トレイと Renderer は、メインプロセスから IPC で状態を受け取って表示する。
  Renderer 側に別の録音状態を持たない。
- 入力ソースの設定は、トレイと設定画面の両方から変更できる。
  変更はメインプロセスに保存し、録音中は現在の設定を表示する。
  録音中に変更した場合は表示だけに反映し、次の録音から適用する（ADR-0002）。
- 会議一覧は、日付、タイトル、長さ、状態（録音中、文字起こし中、要約済みなど）を表示する。
  文字起こし中の会議には進捗を表示する。
  状態は `meta.json` の `status` を次のように表示する。
  `recording` は録音中、`encoding` は変換中、`enhancing` は音声強調中、`transcribing` は文字起こし中、`transcribed` は文字起こし済み、`summarized` は要約済み、`error` はエラーとする。
  タイトルは一覧から編集でき、変更は会議フォルダの改名につながる（ADR-0010）。
- 録音中の入力レベルと無音警告は、メインウィンドウの録音パネルと、会議一覧の録音中の行に表示する。
- 会議詳細は、音声プレイヤー、文字起こし、要約のタブを持つ。
  文字起こしと要約は編集でき、要約の生成とクリップボードへのコピーの操作を置く。
- 設定画面は、保存先フォルダ、whisper.cpp のモデルの選択とダウンロード、LLM プロファイルの一覧と追加、既定のプロファイルの選択、要約の出力言語、BlackHole 2ch のセットアップへの README リンクを持つ。
  プロンプトテンプレートの編集は、PRD の S-7 が Could のため次フェーズに回す。
  グローバルショートカットは採用しない。
- 画面の切り替えは React の状態で行い、URL のルーターは入れない。
  3 つの画面と会議の選択だけで足りるため、ルーターの依存を増やさない。
  About 画面は macOS のアプリメニューに置く標準の画面であり、この 3 つには数えない。
- アプリのインスタンスは 1 つに制限する。
  2 つ目の起動は、既存のウィンドウを前面に出して終了する。
- 録音中はメニューバーのアイコンと経過時間を更新する。
  更新の頻度は 1 秒に 1 回とし、画面全体の再描画を避ける。
- 権限の要求は、初めて必要になった時点で行う。
  マイクは、入力デバイスの検出を初めて行うとき、または録音を開始するときに要求する。
  入力デバイスのラベル取得にマイク権限が必要なため、録音開始まで待つと BlackHole の有無を事前に判定できない。
  ラベル取得のために `getUserMedia({audio: true})` で既定の入力を開かない。
  `systemPreferences.askForMediaAccess` で権限だけを要求し、`enumerateDevices` でラベルが取れるか検証する。
  システム音声は BlackHole 2ch などの仮想オーディオデバイスを入力として使うため、画面収録権限は要求しない。
  保存先フォルダのアクセス権は、初回起動時にテストファイルを書いて確認する。
  権限が拒否された場合は、設定画面からシステム設定の該当箇所を開けるようにする。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| メインウィンドウだけで操作する | 録音の開始と停止のために毎回ウィンドウを開くことになり、PRD のメニューバー常駐の要件を満たせない |
| Dock のアイコンだけで操作する | 会議中に素早く録音を始める入口として弱い。メニューバーの常駐が PRD の前提である |
| 録音専用のフローティングウィンドウを出す | 画面が増え、状態の表示と操作が重複する。メニューバーとメインウィンドウで足りる |
| メインウィンドウを閉じたらアプリを終了する | 録音中にウィンドウを閉じた場合に録音が止まる。メニューバーに残すほうが安全である |
| 複数のメインウィンドウを開く | 会議の選択と録音の状態が重複し、同じファイルを同時に編集する危険がある |
| URL のルーターを入れる | 画面が 3 つで、外部から画面を開く要求もない。状態管理の依存を増やす理由がない |
| ネイティブのメニューバーアプリにする | PRD の Electron 指定から外れる。UI と録音の実装を別の言語で持つことになる |
| 録音の状態を Renderer だけで持つ | メニューバーとメインウィンドウで状態がずれる。メインプロセスを唯一の状態にする |

## 結果

- メインウィンドウを閉じてもアプリが残るため、録音中の誤操作でアプリが終了しない。
  一方で、アプリが起動していることに気付かない利用者もいるため、メニューバーのアイコンを常に見せる。
- トレイと Renderer の状態を同期する IPC が必要になる。
  状態の変更はメインプロセスから一方向に通知し、画面は表示だけを行う。
- メインウィンドウが背面にある間も録音を続けるため、Renderer の background throttling を無効にする（ADR-0002）。
- メニューバーの経過時間を毎秒更新すると、IPC と再描画の頻度が上がる。
  経過時間だけを更新するコンポーネントに分け、会議一覧の再取得を毎秒行わない。
- 権限の要求のタイミングが録音の開始時になるため、初回の録音でダイアログが出る。
  初回起動時に権限の説明を出し、録音開始時に慌てないようにする。
- 画面の切り替えを React の状態で行うと、アプリの再起動後に開いていた画面は復元されない。
  会議詳細を開いていた場合は、最後に開いた会議を復元するかを決める必要がある。
- アプリを 1 インスタンスに制限することで、SQLite と会議フォルダの同時更新を避ける（ADR-0010）。
- プロンプトテンプレートの編集を次フェーズに回すため、MVP の設定画面には編集の項目を置かない。

## 未決事項

- Dock のアイコンを表示するか、メニューバーだけにするか。
- 文字起こしの完了や失敗を macOS の通知で知らせるか。
- URL のルーターを将来入れるか。
- メニューバーのアイコンの状態 (待機、録音中、音声強調中、文字起こし中、エラー) のデザイン。
- メインウィンドウの既定のサイズと最小サイズ。
- 最後に開いた会議と画面を再起動後に復元するか。
- 設定画面にプロンプトテンプレートの編集をいつ入れるか。
- 初回起動時の権限説明とオンボーディングの内容。
