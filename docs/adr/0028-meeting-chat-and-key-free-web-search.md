# ADR-0028: 会議チャットは要約とクリーニング済み文字起こしをコンテキストにし、Web 検索はキー不要の簡易検索を使う

- Status: Accepted

## Context

要約は会議の全体像をつかむには十分だが、「この決定の背景は何だったか」「誰がこの案に反対したか」のような質問には、文字起こしの該当箇所が必要になる。
利用者から、要約の後に会議の内容について AI とチャット形式でやりとりしたいという要求がある(PRD の `REQ-CHAT-001`)。

ADR-0025 は、要約の前に相槌と擬音を除いた本文をファイルとして保存しないと決めた。
そのため、要約に使った本文をチャットのコンテキストに再利用できない。
元の `transcript.md` を使うと、相槌と擬音が回答の品質を下げる。
クリーニング済みの本文を保存し、元の文字起こしが変わったときに無効化する必要がある。

会議の外の情報を調べるために Web 検索を使いたいという要求もある(PRD の `REQ-CHAT-002`)。
利用者は API キーを追加しない簡易検索を選んだ。
検索プロバイダを追加すると、設定、キーの保存、利用規約、料金の説明が増える。

LLM クライアントは system と user の 1 往復だけを送る(ADR-0008)。
チャットでは複数ターンの履歴を送る必要がある。

## Decision

### クリーニング済み文字起こし

- 要約生成時に相槌と擬音を除く設定が有効で、除去に成功したときは、要約に使った本文を `transcript.cleaned.md` として保存する。
- `transcript.cleaned.md` の front matter に `source_sha256`、`provider`、`model`、`generated_at`、`cleanup_state` を持つ。
  `source_sha256` は保存時点の `transcript.md` の本文の SHA-256 とする。
- 除去が一部の区間で失敗したときは `cleanup_state: partial` として保存し、チャット画面に表示する。
- 除去に失敗したとき、除去の設定が無効なときは `transcript.cleaned.md` を削除する。
- `transcript.md` を編集または再文字起こししたときは `transcript.cleaned.md` を削除する。
- タイトル変更と話者名変更は `transcript.cleaned.md` にも反映する。
  話者名変更では `source_sha256` を変更後の `transcript.md` で更新する。
- チャットを開いたときに `transcript.cleaned.md` がない、または `source_sha256` が現在の `transcript.md` と一致しないときは、元の `transcript.md` を使う。
  画面にその旨を表示し、利用者が確認したときに LLM で除去をやり直せるようにする。

### チャットのコンテキスト

- 必須のコンテキストは `summary.md` と `transcript.cleaned.md` とする。
- 要約は 30,000 文字を上限に含める。
- クリーニング済み文字起こしは 60,000 文字以下なら全文を含める。
  超える場合は、質問の語句と一致する行とその前後 2 行を最大 60 行選び、文字数の上限まで含める。
  一致する行がない場合は、冒頭と末尾を含める。
- 会話履歴は直近 20 メッセージ、12,000 文字を上限に含める。
  履歴の先頭が assistant にならないようにする。
- 会議の要約、文字起こし、Web 検索結果はデータとして扱い、その中の指示に従わないようシステムプロンプトで指示する。
  データの区切りにはリクエストごとのランダムな nonce を使う。
- 回答は利用者の質問と同じ言語にし、資料にない事実を推測しないよう指示する。
- Web 検索結果を使った回答には `[1]` のような出典番号を付け、会議の事実と Web の情報を区別するよう指示する。

### チャット履歴

- 会議フォルダの `chat.json` に保存する。
  `schema_version`、`messages`、`last_profile_id`、`context_hash`、`updated_at` を持つ。
- 各メッセージは `id`、`role`、`content`、`created_at`、`profile_id`、`model`、`web_search`、`sources`、`search_error` を持つ。
- 履歴は 100 メッセージ、合計 400,000 文字を上限とし、超えた場合は古いものから削除する。
- 保存は 0600 の一時ファイルに書いて rename する。
  会議を削除すると `chat.json` も削除する。
- `context_hash` は要約の本文と、チャットに使った文字起こしの本文から作る。
  読み込み時に現在のハッシュと異なる場合は、要約または文字起こしが更新されたことを画面に表示する。
- チャットの送信が失敗またはキャンセルしたときは、そのターンのメッセージを保存しない。
- 会議詳細から履歴を消去できる。消去はチャットの実行中には行わない。

### Web 検索

- 検索はメッセージごとのチェックボックスで明示的に有効にする。
  既定値は設定に保存する。
- API キーを要求しない簡易検索を使う。
  Brave Search の HTML を第一候補、DuckDuckGo の HTML を第二候補とする。
  Bing の RSS は CJK を含まないクエリだけ最後のフォールバックに使う。
  Bing の RSS は日本語のクエリで無関係な結果を返すことを確認したため、日本語のクエリでは使わない。
- 検索結果は最大 5 件とし、タイトル、URL、表示用 URL、抜粋を回答のコンテキストに含める。
- Brave Search の結果 URL はリダイレクト URL になる。
  表示用 URL は検索結果の表示 URL とし、出典一覧には表示用 URL のホストを出す。
  出典を開くときはリダイレクト URL を既定のブラウザで開く。
- 検索に失敗しても会議の要約と文字起こしだけで回答する。
  検索に失敗したことを画面とシステムプロンプトに含める。
- 検索語は利用者のメッセージだけを使い、会議タイトル、保存先、音声を送らない。
- 検索結果は 5 分間メモリにキャッシュする。
  キャッシュは 50 件を上限とし、超えた場合は古いものから削除する。
- 検索の送信先は Brave Search と DuckDuckGo であり、利用規約と可用性は保証しない。
  検索エンジンの仕様変更やアクセス制限で使えなくなる可能性を README と画面に表示する。

### LLM クライアント

- `ChatCompletionRequest` に `history` を追加し、`role` が user または assistant のメッセージを現在の user メッセージの前に送る。
- OpenAI 互換 API では system、履歴、現在の user の順に送る。
- Anthropic では system をトップレベルに置き、履歴と現在の user を `messages` に送る。

## Consequences

- 要約に使った本文を後から確認でき、チャットの回答根拠と要約の根拠が一致する。
  一方で、`transcript.cleaned.md` は派生物であり、`transcript.md` の変更で無効になる。
- 会議フォルダにチャット履歴が残るため、要約や文字起こしと同じくバックアップと同期の対象になる。
  履歴の消去と会議の削除を提供する。
- 文字起こしが長い会議では、質問に関連する行だけを送るため、会議全体の細部を一度に質問すると情報が抜ける場合がある。
  要約は常に全文を含める。
- Web 検索は API キー不要で使えるが、検索エンジンの HTML に依存する。
  Brave Search と DuckDuckGo が使えない場合は検索を諦め、その旨を表示する。
  Bing の RSS を日本語で使わないため、CJK のクエリで他の 2 つが失敗した場合は検索結果を返さない。
- 検索語は検索エンジンに送られる。
  送信する内容を画面に表示し、既定では Web 検索を無効にする。
- チャットのプロンプトインジェクションは完全には防げない。
  資料をデータとして扱う指示と nonce の区切りで緩和するが、LLM の判断に依存する。
- 会議チャットの応答時間と料金はプロバイダに依存する。
  送信する概算トークン数を画面に表示する。

## Alternatives

- Brave Search API または Tavily API を使う。
  API キーの保存、料金、利用規約の説明が増えるため、今回は採用しない。
- LLM プロバイダの内蔵 Web 検索を使う。
  Claude と OpenAI で実装が異なり、任意の OpenAI 互換 API では使えないため、今回は採用しない。
- 文字起こしを embedding してベクトル検索する。
  新しい依存と索引の管理が必要で、会議 1 件の文字起こしの長さでは行単位の語句検索で足りるため、今回は採用しない。
- チャット履歴をアプリのメモリだけに持つ。
  再起動で会話が消えるため、会議フォルダに保存する方を採用する。
