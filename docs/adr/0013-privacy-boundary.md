# ADR-0013: 音声を端末外に送らないプライバシー境界を設ける

Created: 2026-10-28
Model: DeepSeek V4.1 Flash 1017
Status: Accepted

## 背景

Kataribe のコアバリューは、音声と文字起こしを端末内に置くことにある。
LLM に送るのは文字起こしの Markdown だけで、しかも利用者が明示的に操作したときに限る（PRD の概要）。
1 on 1 の内容を自分だけの記録として残す用途では、共有しない限り外に出ないことが前提になる（PRD の U3）。
PRD はテレメトリを収集しないとし、文字起こしの送信前に確認ダイアログを出すことを求める（PRD の S-3、「非機能要件」）。
個人名や社名のマスクは対象外で、送信先が入力を学習に使うかを含めたリスクは、プロバイダを選ぶ利用者の判断に任せる。
PRD の「音声と文字起こしは端末の外に出ない」は、文字起こしを LLM に送る場合を含まない表現になっている。
ADR と UI では「音声は端末外に出ない。文字起こしは、要約や翻訳を利用者が実行したときだけ LLM に送る」と統一する。
この表現を確認ダイアログと設定画面でも使う。

この方針を守るには、ネットワークに出る経路を限定し、音声、文字起こし、API キー、ログの扱いを決める必要がある。
「プライバシーに配慮する」という方針だけでは、実装時に不要な通信やログが増える。

## 決定

- 音声ファイルは既定で端末外に送らない。
  クラウドの文字起こし API、音声のアップロード、音声を含むクラッシュレポートを使わない。
  利用者が OpenAI の文字起こし API を明示的に選んだ場合だけ、ADR-0024 の確認手順に従って音声を送る。
- 文字起こしと要約の生成で LLM に送るのは、文字起こしのテキストだけとする。
  音声ファイル、会議フォルダのパス、タイトル、日付、API キー、その他のメタデータは送らない。
- LLM への送信は、利用者が要約の生成や翻訳を明示的に操作したときだけ行う。
  翻訳の保存形式と操作は ADR-0016 で扱う。
  自動送信、バックグラウンド送信、定期的な送信、起動時の送信は行わない。
- 送信のたびに確認ダイアログを出し、プロバイダ名、モデル名、エンドポイントの完全な URL、送る文字起こしの全文またはスクロール可能なプレビュー、文字数、内容のハッシュ、概算のトークン数と料金を表示する。
  利用者が確認したときだけ送信する。
  「次回から確認しない」の選択肢は MVP では持たない。
- 確認ダイアログには、個人名や社名のマスクを行わないことと、送信先のデータの扱いはプロバイダの規約に従うことを表示する。
  プロバイダのデータ保持や学習の条件をアプリが保証しないことを明記する。
- LLM のエンドポイントは HTTPS を必須とする。
  ローカルの Ollama など `localhost` のエンドポイントだけは HTTP を許可する。
- テレメトリ、アクセス解析、利用状況の送信を行わない。
  成功指標は、端末内の `meta.json` と会議フォルダから計算する（PRD の「成功指標」）。
- クラッシュレポートを外部に送らない。
  Electron の `crashReporter` を開始しない。
  クラッシュした場合は、端末内のログと `meta.json` に原因の手がかりを残す。
  ログに文字起こしの本文、要約の本文、API キーを含めない。
- Electron と Chromium のバックグラウンド通信を無効化する。
  スペルチェッカー、コンポーネントの更新、ドメインの信頼性チェック、クラッシュレポートの自動送信など、アプリが明示しない通信を止める。
  具体的なフラグは実装時に検証し、リリース前にプロキシで通信先を監査する。
- アプリのログに残すのは、処理の種類、開始と終了の時刻、終了コード、HTTP ステータス、エラーの分類、使用したモデルとプロバイダ名とする。
  会議の本文と API キーは redaction の対象にする。
- モデルのダウンロードは HTTPS で行い、チェックサムを照合する（ADR-0006）。
  モデルの入手元以外に、モデルの取得を目的とした接続を行わない。
- 自動更新を入れる場合は、更新の確認だけを行い、会議の内容を送らない。
  更新の確認の有無と、無効にする設定を提供するかは未決事項とする。
- Renderer では外部の Web コンテンツを読み込まない。
  CSP を設定し、開発時の Vite のサーバー以外の接続を許可しない。
  Markdown の描画は raw HTML を無効にしたレンダラーとサニタイズを使い、`dangerouslySetInnerHTML` を使わない。
  外部画像と `javascript:`、`file:` のリンクを拒否し、CSP に `script-src 'self'`、`object-src 'none'`、`base-uri 'none'` を入れる。
  `will-navigate` と `setWindowOpenHandler` でアプリ内 URL 以外の遷移を拒否し、`shell.openExternal` は `http:` と `https:` だけを許可する。
  外部のリンクを開く場合は、アプリ内のブラウザではなく、macOS の既定のブラウザに渡す。
- API キーは safeStorage で保存し、メインプロセスだけで復号する（ADR-0009）。
- 保存先ルートが iCloud Drive、Dropbox、OneDrive、Google Drive、既知の Obsidian の同期フォルダなどの場合、最終成果物の音声と文字起こしが端末外に同期される。
  ADR-0010 の検出と警告に従い、利用者が明示的に選んだ場合だけ同期対象のルートを使う。
- 会議データを暗号化して保存するかは未決事項とする。
  MVP では macOS の FileVault とファイルの権限に依存する。
- 録音の相手に録音の同意を得る責任は利用者にある。
  録音の開始時に、録音の事実を周囲に示す必要がある旨を画面に出すかどうかは、未決事項とする。
- 利用者が要約をクリップボードにコピーした場合、コピー先のアプリは OS のクリップボードから内容を読める。
  コピーは利用者の明示的な操作であり、アプリはクリップボードの内容を外部に送らない。

## 検討した選択肢

| 選択肢 | 採用しない理由 |
| --- | --- |
| クラウドの文字起こし API を既定にする | 音声が既定で端末外に出る。コアバリューと U3 に反する。ADR-0024 で、利用者が明示的に選んだ場合だけ使う任意のエンジンとして追加した |
| 利用状況のテレメトリを opt-in で送る | 便利だが、PRD はテレメトリを収集しないと明記している。会議の内容に触れないテレメトリでも、方針を曖昧にする |
| 文字起こしを自動で LLM に送る | 会議のたびに送信の判断を利用者から奪う。S-3 に反する |
| 送信前に個人名や社名をマスクする | マスクの精度と誤検出の責任が大きく、PRD の対象外になっている。プロバイダの選択と利用者の判断に任せる |
| クラッシュレポートを外部に送る | 会議の本文やパスが含まれる可能性がある。端末内のログに限定する |
| ローカルの LLM だけを使う | 音声も文字起こしも外に出ないが、利用するモデルとハードウェアに品質が依存する。PRD は任意のプロバイダを求めている |
| 会議データをアプリ独自の暗号化で保存する | 鍵の管理が必要になり、MVP の範囲を超える。FileVault とファイルの権限で当面をしのぐ |
| 自動更新を最初から入れる | 更新の確認は会議の内容を送らないが、通信の経路が増える。必要になった時点で、送る情報を明記して入れる |

## 結果

- 音声と文字起こしの保存は端末内で完結し、ネットワークが必要なのは OpenAI 文字起こし、LLM の送信、モデルのダウンロードだけになる。
  OpenAI 文字起こしは既定で無効であり、送信のたびに確認する。
- テレメトリとクラッシュレポートが無いため、不具合の再現と改善は利用者から提供されたログとファイルに頼ることになる。
  ログの内容と取得の手順を整備する必要がある。
- 送信のたびに確認ダイアログが出るため、要約の生成に 1 ステップ増える。
  会議の内容を送る判断を利用者に残すためのコストとして受け入れる。
- プロバイダのデータ保持と学習の条件は、アプリの外にある。
  確認ダイアログと設定画面で、プロバイダの規約を確認するよう促す。
- HTTPS を必須にすると、localhost 以外の HTTP エンドポイントを使う利用者には設定の変更が必要になる。
  `localhost` の例外を用意し、それ以外の HTTP は拒否する。
- Renderer の CSP と外部コンテンツの制限により、将来の UI の作り方に制約がかかる。
  外部のウィジェットや埋め込みを使う場合は、この ADR の見直しが必要になる。
- 会議データの暗号化をしない場合、ディスク全体の暗号化とファイルの権限が最後の防御になる。
  FileVault が無効な環境では、会議の内容が読み取られる可能性がある。
- 録音の同意の表示を入れる場合は、初回の録音の前に 1 ステップ増える。
  法律上の要件は国や地域によって異なるため、アプリは一般的な注意喚起に留める。

## 未決事項

- 会議データを保存時に暗号化するか。
  暗号化する場合の鍵の保存方法と、SQLite の索引の扱い。
- バックグラウンド通信を無効化する具体的なフラグと、残る OS の通信の扱い。
- Markdown のサニタイズと CSP のテスト方法。
- 同期対象のルートを選んだ場合の警告の文言と、音声を同期しない設定。
- ローカルのログの保存場所、保持期間、利用者による削除の方法。
- 録音の同意を得るための注意喚起を、初回起動時と録音開始時のどちらに出すか。
- 自動更新の確認を入れるか。
  入れる場合に送る情報と、無効にする設定。
- クラッシュしたときのローカルレポートの形式と、利用者が開発者に提供する手順。
- プロバイダのデータ保持と学習の条件を、確認ダイアログにどこまで表示するか。
- `localhost` 以外の HTTP エンドポイントを許可する必要があるか。
- クリップボードにコピーした要約の扱いを、利用者にどこまで注意するか。
- テレメトリの代わりに、端末内で成功指標を集計して表示するか。
