# ADR-0027: RE-USE を WebGPU でアプリ内実行し、録音停止後と文字起こし前の音声強調を追加する

- Status: Accepted

## Context

ADR-0026 は、RE-USE を録音の入力時にも文字起こしの前処理にも採用しないと決めた。
日本語の会議風音声では文字起こしの CER が改善せず、低い SNR では悪化したためである。
一方で、利用者は実会議の音声で比較を続けたいとして、次の 2 点を求めた。

- アプリ内で実会議の音声を比較し続けるために、外部の Python 環境を用意せずに使いたい
- 録音停止後の保存音声と、文字起こし前の 16 kHz 音声のそれぞれで ON/OFF できる

RE-USE は 9.6M パラメータの双方向 Mamba を使うオフラインモデルで、8 kHz から 48 kHz のモノラル音声を入力にする。
公式の推論は Linux と NVIDIA Ampere の GPU を前提とする。
macOS では、非公式の PyTorch 移植か、手書きの WebGPU カーネルを使う実装がある。
WebGPU 実装は MIT ライセンスで、モデルの重みを除いたコードは約 1,200 行である。
重みはモデルごとに約 38.6 MB で、商用利用が可能なモデルは OpenMDW-1.1、研究および教育用のモデルは NSCLv1 である。

ADR-0026 は文字起こしの品質改善を理由に RE-USE を採用しなかった。本 ADR は、保存音声と文字起こし前の音声強調という別の用途を扱う。

アプリは本体サイズを 300 MB 以下に保つ必要があり、PyTorch を同梱できない。
WebGPU が使えない環境がある。

## Decision

- WebGPU の RE-USE エンジンをアプリに同梱する。
  対象は STFT と iSTFT、safetensors の読み込み、重みのパッキング、WGSL カーネル、モデルの実行、チャンク処理である。
  MIT ライセンスの表示を残し、モデルの重みは同梱しない。
  同梱するコードは `geronimi73/re-use-demo` の commit `0d54dca074597b111a8e8c78f6067a6fa0231f75` とする。
  エンジンの出典 commit とライセンス本文を `resources/licenses/` に置き、アプリメニューのライセンス項目と設定画面から参照する。
  公式の推論経路が提供されたら、WebGPU エンジンをその経路に置き換える。
- アプリが使うモデルは、商用利用が可能な `nvidia/NVIDIA-NemotronLabs-RE-USE` だけとする。
  研究および教育用の `nvidia/RE-USE` はアプリの選択肢に含めない。
  2 つのモデルの比較は、配布物の外で `docs/testing/reuse-speech-enhancement.md` の手順に従って行う。
- モデルの重みは初回利用時にダウンロードする。
  モデル ID ごとにファイル名を分け、SHA-256 を照合し、進捗、キャンセル、削除を提供する。
  インストール済みのファイルも使う前に SHA-256 を照合する。
  強調ジョブが使っているモデルの削除は拒否する。
- 録音停止後の保存音声の強調と、文字起こし前の強調を、別々の設定で ON/OFF できるようにする。
  どちらも既定は OFF とする。
- 録音停止後の強調は、生の `audio.mp3` を残し、`audio.enhanced.nemotronlabs.mp3` を追加する。
  会議詳細から、インストール済みの商用モデルで再実行できるようにする。
  再実行の入力は `audio.mp3` からデコードした WAV であり、録音した会議では録音直後の元 WAV とは異なる。録音した会議では、入力が異なることを画面に表示する。
  再実行に成功したときは以前の強調音声を新しい結果で置き換え、失敗したときは以前の強調音声を残す。
  `audio.mp3` のハッシュが変わったときは、古い強調音声を削除する。
  モデルの SHA-256 が変わったときは、古い強調音声を削除する。設定だけを変えたときは、再実行するまで残す。
  会議詳細の音声プレイヤーで、生音声と強調音声を切り替えて再生できるようにする。
- 文字起こし前の強調は、比較セッションで実行する。
  比較セッションは、1 つの 16 kHz WAV から生と強調の文字起こしを作る単位とする。
  比較セッションは `audio.mp3` から 16 kHz WAV を 1 回だけ作り、生の文字起こしと強調の入力の共通の親にする。
  強調した 16 kHz WAV はその WAV から作る。
  比較用に `transcript.raw.md` と `transcript.nemotronlabs.md` を保存し、初回の文字起こしでは強調した結果を `transcript.md` とする。
  初回の文字起こしで強調に失敗したときは、生の結果を `transcript.md` とし、比較用は成功した側だけを保存する。
  初回の文字起こしで両方に完了結果がないときは、`transcript.md` に部分結果を保存する (ADR-0007)。比較用は完了した側だけを保存する。強調した文字起こしに部分結果があればそれを、なければ生の部分結果を `transcript.md` とする。部分結果が 0 セグメントのときは `transcript.md` を作らない。
  比較用の文字起こしは読み取り専用のスナップショットとし、本文は生成時の内容を保持する。front matter の title は会議タイトルに追従する。
  文字起こし前の強調を再実行するときは、既存の `transcript.md` を `transcript.previous.md` にコピーし、上書きを確認する。コピー後も `transcript.md` は成功するまで変更しない。
  再実行は、生と強調の両方の文字起こしが成功したときだけ成功とする。
  成功したときは比較用の文字起こしと `transcript.md` を新しい結果で置き換え、どちらかが失敗またはキャンセルしたときは以前の結果を残す。
  比較用の文字起こしは、`audio.mp3` のハッシュが変わったとき、文字起こし前の強調を OFF にして再文字起こししたとき、OpenAI の文字起こし API を選んだとき、比較セッションの入力が変わったとき、モデルの重みの SHA-256 が変わったときに削除する。
  会議詳細で生と強調の文字起こしを切り替えられるようにする。
  `transcript.md` を要約と翻訳の正とし、ToDo は `summary.md` を正とする。比較用の文字起こしは要約、翻訳、検索、ToDo の入力にしない。
  再実行に成功したときは、既存の要約と翻訳が以前の文字起こしに基づくことを会議詳細に表示する。
- 文字起こしエンジンの解決は会議処理の開始時に 1 回だけ行い、比較フロー全体で同じ解決結果を使う。
  OpenAI の文字起こし API を選び、送信を承認したときは、文字起こし前の強調が ON なら強調した音声、OFF なら生の音声を 1 回送る。
  強調に失敗したときは生の音声を送る。
  送信の確認ダイアログには、強調の設定と成否に応じて送る音声を表示する。
  送信を承認しなかったときはローカルの whisper.cpp に切り替え、設定に応じて比較フローまたは通常のローカル文字起こしを実行する。
  強調に失敗したときは生の音声だけで文字起こしする。
- `enhancement.json` を音声強調の状態の正本とする。
  項目は、形式のバージョン、`audio.mp3` の情報、保存音声の強調、文字起こし前の強調を持つ。
  各結果に入力と出力のハッシュ、使用モデル、処理設定、開始と終了の時刻、処理時間、状態、エラーを記録する。
  `meta.json` は会議一覧に必要な状態の要約だけを持ち、詳細な状態を重複して持たない。
  書き込みは一時ファイルと rename で行い、読み込みに失敗したときは派生ファイルを残したまま警告を表示する。
- 話者分離のキャッシュキーには、会議の `audio.mp3` の SHA-256、入力の種類 (`raw` または `enhanced:<model>`)、強調モデルの SHA-256、強調設定を含める。
  `raw` のときは PCM 由来と mp3 由来の WAV を同じキーにし、通常の再文字起こしでキャッシュを再利用する。
  強調の有無、モデル、設定の変更で古いターンを再利用しない。
  キャッシュ形式のバージョンを上げ、`input_kind`、`enhancement_model_sha256`、`enhancement_settings` を必須にする (ADR-0021)。
  話者分離は `transcript.md` にだけ行い、比較用の文字起こしには行わない。
- 強調はメインウィンドウの Renderer に作る専用の Web Worker で実行する。
  メインウィンドウは閉じても破棄されず隠れるため、処理中は Worker が生存する。
  ウィンドウが破棄された場合は処理を失敗させ、生の音声を残す。
  音声はカスタムプロトコルで読み、5 秒程度のチャンクに分けて処理し、強調したチャンクを逐次書き出す。
  44.1 kHz または 48 kHz の長い音声でも、全体を Float32 の配列として保持しない。
- 音声とモデルの読み込みには、許可したパスだけを返すカスタムプロトコルを使う。
  モデル ID と一時ファイルのトークンを許可リストで照合し、期限切れのトークンを拒否する。
  Renderer から任意のファイルを読ませない。
  スキームは `kataribe-temp` と `kataribe-model` とし、Renderer の Worker から fetch するため `corsEnabled` を有効にする。
  Range リクエストには `206` と `Content-Range` を返し、音声を全体としてメモリに読み込まない。
- 音声強調の一時ファイルは、保存先ルートの外の `~/Library/Application Support/Kataribe/tmp/<meeting-id>/` に置く。
  音声強調の `audio.16k.enhanced.wav` と mp3 からデコードした一時 WAV は、成功、失敗、キャンセルのいずれでも削除する。
  `audio.16k.wav` は ADR-0005 に従う。
  起動時に、復旧データを持たない会議の一時ディレクトリを削除する。`status` が `error` の会議、または `transcription.state` が `partial`、`failed`、`cancelled`、`interrupted` の会議は、`chunks/` と `audio.16k.wav` を残す。比較セッションの生と強調のどちらかが完了していない会議も残す。
  開始前に必要な空き容量を確認する。
  音声強調の処理中は、会議の状態を `enhancing` として表示する。
- 音声強調は端末内の WebGPU で行い、音声を外部に送らない。
  WebGPU が使えないとき、または GPU メモリが足りないときは、CPU にフォールバックせず、機能を無効にして理由を表示する。
- この機能は、商用利用が可能なモデルで生の音声と強調した音声を比較するために追加する。
  文字起こし精度が上がるとは主張せず、既定 OFF の任意機能とする。
  比較の結果、文字起こし精度の改善が確認できなければ、比較機能を削除し、生の音声と文字起こしだけを使う経路に戻す。
  モデルのダウンロードと保存音声の強調を残すかは、別の要求として判断する。

## Consequences

- アプリは PyTorch を同梱せず、モデルの重みだけを初回にダウンロードする。
  本体のサイズを抑えられる一方で、WebGPU エンジンの非公式コードを保守する負担を負う。
- WebGPU の可用性と GPU メモリに依存する。
  古い macOS、GPU の制限、他のアプリの GPU 使用状況で処理できない場合がある。
- 音声強調の処理時間は、音声の長さとサンプルレートに比例する。
  長い会議では進捗とキャンセルを提供する。
  M4 Pro (48 GB) の実測では、2 秒の音声を 16 kHz で 455 ms、44.1 kHz で 708 ms、48 kHz で 747 ms で処理した。
  60 分への線形外挿は 16 kHz で 13.7 分、44.1 kHz で 21.2 分、48 kHz で 22.4 分であり、PRD の目標値 (16 kHz で 15 分以内、44.1 kHz または 48 kHz で 25 分以内) を満たす。
  M1 と M3 では未測定である。
- アプリが扱うモデルは商用利用が可能な 1 つだけになる。
  研究および教育用のモデルを比べる利用者は、配布物の外の検証手順を使う必要がある。
- 生と強調の音声、生と強調の文字起こしを保存すると、ディスク使用量と UI の選択肢が増える。
  どちらも OFF にした会議は従来どおり 1 つの音声と 1 つの文字起こしにする。
- 話者分離のキャッシュキーが増える。
  強調の有無、モデル、設定を変えたときは、話者分離をやり直す必要がある。
- 音声強調の一時 WAV は、60 分の会議で数百 MB になる。
  成功時、失敗時、キャンセル時、復旧データを持たない会議の起動時の削除、空き容量の確認が必須になる。
- 比較の結果、文字起こし精度の改善が確認できなければ、比較機能を削除する。
  保存音声の強調とモデルを残す判断は、別の要求として行う。
